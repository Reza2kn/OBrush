# Source Brush Lock: static implementation boundary

This is a source-grounded design note, not an implementation or parity claim. The pinned reference checkout is `.tools/sculptgl-reference/upstream` at `8e45dafc0f7906e5238dfffc1a2df742bd25f29d`. The failed [C273 normal-UI pair](SCULPTGL_BRUSH_LOCK_UI_C273.md) is a hard blocker to promoting OBrush's existing legacy `LockedStamp` route for Source Brush Lock.

## Reference state transitions

`src/gui/GuiSculptingTools.js:77-78` exposes the tool's `_lockPosition` checkbox. `src/editing/tools/SculptBase.js:28-57` performs a normal surface hit, initializes the alpha frame, pushes one geometry-history state, and records press mouse coordinates. `startSculpt()` at lines 67-71 deliberately skips the initial dab when locked. `update()` at lines 92-95 delegates held input to `updateSculptLock()`.

For each non-continuous held update, `updateSculptLock()` (`SculptBase.js:99-120`) first calls the current state Undo to remove the *previous preview*. It computes `dx,dy` from the fixed press coordinates, temporarily sets `_radius = hypot(dx,dy)`, and calls `makeStroke()` at only `1e-3` screen units along the travel direction from the press. It restores the prior radius after the call and renders. This makes the stamp grow with the drag while its hit and alpha origin stay at the press. A zero-length drag is not a usable stamp; its divide-by-radius behavior should be characterized explicitly before admitting it. `makeStroke()` (`:157-185`) ray-picks at the near-press synthetic point, selects vertices inside the current local radius, computes the picked normal, disables dynamic topology while locked, then invokes the tool stroke. Continuous locked updates call `update(true)` (`:195-204`), without the same previous-preview Undo, so they need a separate gate.

`src/editing/tools/Brush.js:21-53` skips proxy refresh while locked, pushes the selected vertices to history, and skips dynamic topology. It obtains the selected front vertices and optional culling, updates the picking alpha with `keepOrigin=true`, then uses the ordinary Brush or Clay response. In plain Brush, `Brush.js:57-89` uses the *current* vertex array as `vProxy` whenever locked, even when Accumulate is off; it computes cubic falloff, multiplies the raw unprotected material channel, pressure intensity, radius factor and alpha, and moves along the picked normal. This kernel is distinct from OBrush's legacy `LockedStamp` Draw kernel. The alpha rotation and footprint depend on `src/math3d/Picking.js:79-99`: `_alphaSide = local_radius * sqrt(1/2)`, direction from frozen `_alphaOrigin` to the synthetic near-press hit, projection onto the picked-normal tangent plane, `lookAt` frame, and retained origin. The alpha sampler at `Picking.js:60-77` applies the image aspect ratio, mirrored X sign when applicable, and nearest integer texel lookup. The radius is recomputed at the synthetic pick via `Picking.js:378-394`, which projects and unprojects a horizontal screen-radius offset at the current hit depth; matching the physical drag in CSS space alone is insufficient.

## Smallest OBrush boundary

Keep the gesture owner in `crates/obrush-app/src/source_geometry_host.rs::SourceGeometrySession`: capture the press screen point, object/level/pose binding, Source options, alpha/mirror tracks and one history claim. On held move, pass the current pointer and captured press point to a **new shared-core Source locked-preview operation** in `obrush-core`. The operation should derive Source's temporary `hypot` radius and `1e-3` directional synthetic hit using the captured `PaintViewCapture`, prepare its contact through the existing Source geometry picker/selection, and run the existing `SourceGeometryStroke` Brush/Clay kernel with captured controls. Native and browser then use the same geometry, normal, alpha and history code; the host only supplies input and renders the returned change envelope.

That core operation needs a transactional `replace_locked_preview` boundary on `Document`/`SourceGeometryStroke`, rather than the legacy `LockedStamp`. It must restore previous preview positions, Source transient normal state, proxy/touched/selection state and alpha frame *without* closing the single stroke or spending redo, then apply the next preview atomically. Press must produce no dab. The final preview becomes the single released history step; cancellation restores the full before state. A rejected ray, stale object/pose, alpha error, memory limit, or history failure must leave a complete prior admitted preview or exact before state, never a mixed partial mesh. The render change envelope must include both vertices reverting from the former preview and vertices changed in the new preview, plus their normal-neighbor closure, so resident GPU words follow the public document at every held frame.

The current `SourceGeometryAlphaTrack::updated()` in `crates/obrush-core/src/source_geometry_controls.rs` always replaces `origin` with the new pass center. A lock-specific `keep_origin` path should preserve the press origin while updating `side` and frame from the tiny directional hit, matching `Picking.updateAlpha(true)`. Avoid changing the ordinary moving-brush behavior. The existing `Document::prepare_source_geometry_controlled_dab()` and `SourceGeometryStroke::apply_controlled()` in `source_geometry_document.rs` / `source_geometry.rs` are the intended selection, normal and deformation path; `SourceGeometrySession::begin_with_controls()` already captures alpha, mirror, pose and claim but its `blocker_controls()` currently rejects lock. Only remove that blocker once the locked core transaction and paired gate pass. Source-mode UI can then expose the checkbox without silently falling back to legacy geometry.

The next check should reuse the frozen C273 fixture/controls/tolerance and prove exact repeated endpoint, equal horizontal/vertical stamp radius, stable press center, distinct asymmetric-alpha rotation, public Save/Undo/Redo, all changed RGB IDs, and active GPU position/display-normal words. Preserve the current failure and cover zero motion, off-mesh motion, cancellation, pressure and symmetry separately. C273's initial before mesh and horizontal ray calibration were exact, but the legacy trial changed 87 IDs versus the reference's 26 and differed by up to `0.0071530938148498535`; these are substantive geometry failures, not rounding or a renderer-only issue.
