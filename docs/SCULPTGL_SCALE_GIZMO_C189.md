# C189 world-axis scale gizmo

C190 subsequently replaced this turn's axis-drag calculation with the pinned SculptGL screen-distance policy and added the uniform ring. The C189 measurements below are preserved as historical evidence for that earlier build.

The normal desktop/browser transform mode now draws square X/Y/Z scale handles beyond the existing translation arrows. A drag measures absolute motion against the frozen camera and world axis, previews a positive scale around the selected world pivot without changing mesh buffers or document history, and commits through the shared Rust selected-group axis-scale transaction once on release. The existing respect-masks option is passed to that transaction. Escape, focus loss and mode switches clear the preview; the existing command barrier finishes a held drag before Save or other document commands.

The independent 266-vertex, two-part browser fixture used by `scripts/check-transforms.mjs` exercises a real pointer drag on the active part. The checked X factor is 1.254976511001587 around world pivot `[2,0,0]`; the maximum position-component difference against the independent axis-scale calculation is `2.3439908058975334e-7`. During the held drag, the rendered view-projection matrix changes while saved revisions and GPU mesh buffers do not. Release advances the document revision once, and Undo/Redo restores exact complete saved projects. A separate native host test checks camera-frozen absolute pointer chunking and exact history; a posed imported-mesh test checks world-pivot preview composition and inverse-transpose normals.

The first browser run passed preview, geometry and history checks but failed its `single_commit` assertion because the harness sampled the revision *after* Undo/Redo. That failed result is preserved under `.artifacts/transform-browser/scale-handles-c189-a5a25392-8f08-42f1-91ac-8d07e0fdf1a6/result.json`. The corrected harness samples immediately after release. The final-source 14-workflow run passed at `.artifacts/transform-browser/scale-handles-c189-release-032b1e5e-ed4d-4fef-8cc8-2f88de49c9a2/result.json` (SHA-256 `a266e2e6d6c4207ae6a06f398539383f5645c9e60846038823cf78f079083a40`), with no browser exception or console error. Its historical status string says “thirteen” because the new case was added without updating that label; the result has 14 case records, all with true gates. The label has since been corrected in the harness. This run used app WASM SHA-256 `279bd4d1c70d4a7130b6322c6d0d0585f1a0de9ab7d7485e28e1de715b266daf`.

The final renderer also uses previewed world centers when sorting transparent parts during a scale drag. `cargo fmt --all -- --check`, the full workspace test suite, native and wasm32 strict workspace Clippy, `scripts/build-web.sh` and `scripts/package-macos.sh` passed; the packaged local app signature verified. The full workspace test log is `.artifacts/scale-gizmo-c189/workspace-tests-delivery.log` (SHA-256 `902fcb37c098bf2c9efd67bc15aead0d1e7d70e65f7955d95311b017d3df0881`).

The pinned SculptGL runtime's physical scale-handle gesture and matching visible mesh remain unpaired. Uniform ring scale, rotation handles, mask-weighted/selected-group scale drag in a normal browser, native GUI pointer behavior and sustained large-mesh latency are still open. This narrows one Transform workflow gap; it does not establish Transform-family, SculptGL or ZBrush parity.
