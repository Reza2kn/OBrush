# C266: four-call selected-row trial preregistration

The [C265 trial](SCULPTGL_RENDER_ROW_RANGES_C265.md) cut active-minute VBO `bufferSubData` traffic to 207.7 MB but submitted 79,965 geometry calls and failed all four frozen million-vertex responsiveness gates. This follow-up changes only the selected-row call cap from 128 to **four**. The same bitwise row scan, deterministic smallest-gap coalescing, 4 KiB additional-call cost, legacy chunk-plan choice, 128-changed-chunk full-buffer fallback, shared core/document, and browser harness remain in place.

Run the same 999,002-vertex/1,998,000-triangle fixture and frozen 60-second, 400-requested-moves/s protocol SHA-256 `234870ed03a240931a22f421968917efaeed8becc1df834c998bbe3e9c101a33` in a fresh owned Chrome profile. Expected VBO subdata calls: at most four per selected upload and therefore under 4,000 for approximately the C265 919-dab delivery count. Coalescing will raise transferred bytes above C265's 207.7 MB, but should remain below C264's 3.45 GB. Predeclare the decision: retain the renderer change only if file/history/shape checks pass, the callback/RAF timing does not regress materially from C264, and it reduces at least one failed responsiveness measure without introducing a new failure. A separate run with different delivered input counts is observational, not a causal speedup ratio; no SculptGL or ZBrush parity follows from this trial. Preserve any failed outcome.

## Rejected four-call result

The owned Chrome run completed 1,001 Source dabs, with zero queued at the end and no observer overflow, app/console error, or GL error. The actual geometry VBO (buffer 7) received 3,940 `bufferSubData` calls and 3,316,890,200 bytes during the active minute. This met the four-call cap but saved only about 4% of the C264 VBO traffic while making about four times as many VBO calls. The selected-row scan averaged 4.298 ms over 1,001 samples. Mesh-upload CPU mean was 10.018 ms (C264: 10.328 ms); active RAF interval P95 was **66.7 ms** (C264: 66.7 ms), app RAF callback CPU P95 was **62.8 ms** (C264: 68.0 ms), and release acknowledgment was 152.8 ms (C264: 159.0 ms). All four responsiveness gates remain failed. The runs delivered different dab counts, so these values cannot establish a causal speedup. The small observed timing differences do not justify retaining the extra scan/GL-call complexity.

The independent audit passed all 17 reported file/history/geometry checks. It counted 40,729 changed vertices and 82,278 changed faces, with no new degeneracy or changed-face orientation reversal. Both C265 and C266 renderer code trials are rejected. The existing selected-chunk renderer stays authoritative.
