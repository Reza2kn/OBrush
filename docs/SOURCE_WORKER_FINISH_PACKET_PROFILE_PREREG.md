# Source Worker final-packet attribution: static finding and proposed profile

**Status:** preregistered design only. No product, packet, parser, browser, or benchmark change is claimed. This is separate from the retained warm decoder, which another worker may own. The frozen SP-WORKER-01 input remains protocol SHA-256 `800641d09091e55df4618c5e76b97186f74e96ecf34872dd335e316e01cd7443` on the independent 99,602-vertex SGL SHA-256 `8f8d76f0d71e420a81358a0a44d3a4ffa2a3ac76e9221165e1359c8e720a7093`.

## What the retained receipts prove

The rejected validation-once 100k receipt (`aae539b5676cd477b1ca64836e4394124dc18850e7fc456ed44c5f95ca93f7d7`) reports a 16,341,256-byte final Worker reply and 195.0 ms from main-thread `finish` post to main-thread reply receipt. Independent comparison of the public Before/After position and normal f32 words gives 4,262 changed rows, hence an 88 + 28 × 4,262 = **119,424-byte** checked geometry delta. The remaining **16,221,832 bytes** are the retained warm packet. The exact v1 layout accounts for 116 header/checksum bytes and 4,780,945 bytes of generation, center, exact position words, face/vertex normal words and selected-chunk bits. The remaining **11,440,771 bytes (70.5% of the retained packet)** encode the historical ordered tree. These are format arithmetic and receipt observations, not a captured raw packet or a compression ratio.

Two other owned 100k receipts with essentially the same final size measured 16,342,112 bytes / 200.3 ms and 16,341,088 bytes / about 198.1 ms. The postMessage call transfers both `Uint8Array` backing buffers; it does not structured-clone their 16 MB contents. The existing Worker `finish` message carries no internal phase timing. Its ~195–200 ms interval therefore includes queued dispatch, `transaction.finish`, full checked delta encoding, retained-state/tree encoding and checksum, wasm-bindgen `Vec<u8>` to JS typed-array copies, transfer setup and event delivery. Packet size alone has **no established causal timing coefficient** from these near-equal-size runs. Independently, the latest main-thread held commit took 453.3 ms and active RAF max 450.1 ms; eliminating the whole 195 ms pre-commit interval would still leave that RAF failure. The packet is a plausible contributor to release-to-commit latency, not an established cause of the main-thread frame stall.

## Read-only attribution run before a transport candidate

With an exclusive Cargo/browser lane, add temporary, bounded phase timers to the Worker `finish` path: queue wait; `transaction.finish`; checked delta encode; retained warm encode including checksum; wasm-bindgen `take_delta` and `take_retained`; `postMessage` call; and main-thread reply arrival. Record both packet component lengths, actual active UI endpoint, applied dabs and whether transfer lists contain both buffers. Use duration measurements within each realm and the already observed main-thread finish round trip; do not subtract uncalibrated Worker and window clocks. The probe must not retain packet contents, change publication/queue ownership, alter the frozen input or verifier, or add work inside the measured component beyond timer reads. Hash its exact patch, served WASM/JS and frozen runner; run focused nonpublication tests; remove probe afterward. Preserve all failed raw receipts.

A format/transport candidate is admitted only if packet encoding plus WASM-to-JS copy and transfer setup plausibly account for **at least 40 ms** of the 100k finish interval, and a same-packet microbenchmark confirms the proposed replacement has at least 40 ms net reduction including decode. Otherwise stop at attribution: optimizing byte count has no supported user-latency claim. Different delivered dab counts prohibit a causal browser speed ratio.

## Conditional security-equivalent candidate

If the above gate admits it, trial a versioned, lossless retained-tree packet encoding, scoped to the historical tree segment; leave public OBJ/.obrush JSON, geometry delta, mesh and state fingerprints, and Source arithmetic unchanged. The encoder must preserve every f32/f64/u32/u64 bit and ordered row, including signed zero, NaN rejection behavior, parent/child/free-list layout and future-dab tree identity. The decoder checks a bounded compressed length and an explicit bounded uncompressed length **before** allocation, verifies checksum and exact expansion length, then runs the existing full warm parser, tree/ring/face-box checks, state fingerprint, mesh binding and one-use host revision/history checks before publication. Malformed compressed data, oversize expansion, stale target/scene/mesh, truncation, checksum mismatch and late failure must be atomic. Version 1 packets remain accepted only where current compatibility requires them; no silent downgrade from malformed v2 to v1. Retain the original raw packet and patch for exact replay. Avoid approximate bounds or reconstructing a fresh tree: both can change selected-row normals and subsequent dabs.

Predeclare a same-mesh/same-packet native and WASM benchmark that includes compression, transfer-facing copy and decompression/parser costs, exact decoded state/future-dab words, and peak allocation. Then run one unchanged 100k normal-browser cohort. Correctness gates are exact independent public Before/After/Stable/Undo/Redo files and one-step history, whole-file shape audit (no new degeneracy/reversal; edge-stretch bound), unique active VBO positions, a separately qualified Source display-normal producer-to-VBO oracle, endpoint fidelity, zero GL/JS errors, and empty Worker queue by 100 ms. Preserve the frozen saved-mesh-normal GPU failure separately because that oracle is invalid for Source display. Performance gates include no worse main-thread commit or retained decode, at least 40 ms less in the independently timed Worker finish construction/copy stages on the same packet, and the existing RAF max ≤250 ms, RAF P95 ≤33.34 ms, app CPU P95 ≤16.667 ms, release acknowledgment ≤100 ms and pacing limits. A failure rejects the candidate and stops before 1m. No packet or codec change alone establishes SculptGL/ZBrush parity.
