# C260 signed-offset curved Draw: failed direct-ID gate, diagnosed import permutation

The preregistered [C260 protocol](SCULPTGL_SYMMETRY_CURVED_C260_PROTOCOL.md) was run twice in separate owned Chrome sessions at 1600×1000/DPR1, using the normal visible controls, independent 4,514-vertex irregular curved SGL fixture, per-mesh normalized SymOffset `+0.25` and `-0.25`, and trusted mouse pressure `0.5`. The full SculptGL symmetry and Draw rows remain open. The **frozen direct-vertex-ID geometry candidate fails for both signs**; do not promote the subsequent remapping diagnostic into the preregistered result.

Root product code had not changed since the official build.

The **earliest measured divergence occurs before either stroke**: the two imports contain a bijective set of 4,514 baseline coordinates with maximum paired coordinate error `5.23682e-8`, but only six numeric vertex IDs correspond. SculptGL's pinned `Mesh.initTopology` in the pinned local `.tools/sculptgl-reference/upstream/src/mesh/Mesh.js` invokes `optimize`; `optimizePreTransform` explicitly rewrites vertex arrays and face indices in face-encounter order. OBrush retains the source order. Thus the frozen direct-ID comparison joined unrelated physical vertices. This is a comparison-indexing failure, not evidence of a product import geometry defect. The public SGL contract need not preserve SculptGL's private optimized vertex IDs.

Other pre-deformation and admission gates matched. In both signs, all three direct and mirrored reference rays hit the active curved object. Normalized loose-root mirror radius was exactly `1.7969753742218018` on both pages; camera path-span relative error was `4.39e-8`; both had four admitted stroke calls, raw pressure and factor `0.5`/`1`, 120 CSS-pixel radius, and local radius about `0.3941747` (paired difference below `2e-7`). Reference changed 158/+ and 175/− vertices, OBrush 160/+ and 175/−; parked-cursor crops changed 10,416/11,374 pixels for + and 5,665/6,658 for −. Each normal Ctrl+Z and Ctrl+Y restored all vertices exactly in its own app; OBrush normal Save bytes for before/undo and after/redo were identical, and its stroke raised undo depth by one. Neither browser reported a WebGL error.

As an **exploratory posthoc diagnostic**, [`analyze-sculptgl-symmetry-curved-c260.py`](../scripts/analyze-sculptgl-symmetry-curved-c260.py) bijectively matched the unmodified baseline coordinates before comparing deltas. It rejected ambiguous/missing matches and required every baseline pair within `1e-6`. After this mapping, + had changed-ID IoU `0.9875`, maximum error `0.000664911`, RMS `0.0000366391`; − had IoU `0.988636`, maximum error `0.000882949`, RMS `0.00004915`. These numbers support a narrower hypothesis that the shared Draw geometry is close under a valid correspondence. They are not preregistered C260 passes. Exploratory outputs and their SHA-256 hashes: + `e562a8e270bc6805c2d63e28e06c76ea4c64b81c73716a711fea8c93be860efe`, − `06ea239077419c3c64e0dd757774601a2b6c3f2cf893cc66929d241d3d82f9ac`.

A new independent gate should freeze the baseline-coordinate correspondence algorithm, uniqueness and negative controls before stroke, then run both signs again. Pixel counts remain descriptive, and neither this fixture nor the earlier triangle establishes full-feature parity.
