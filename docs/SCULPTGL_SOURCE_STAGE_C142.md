# C142: Source brush stage timing and rejected CPU shortcut

The normal OBrush browser still applies Source Brush geometry in shared Rust/WASM and draws through WebGL2. C142 adds read-only timing around the existing controlled-dab preparation and deformation stages. A focused core/app test compares the timed and ordinary paths for exact saved-document and Undo behavior. The production browser was rebuilt with `scripts/build-web.sh`; its app WASM SHA-256 is `a832cf33cb75a43e96ce50f8b098df3985509abc109901c0953ca945fd5df117`.

The frozen [C141 protocol](SCULPTGL_SOURCE_TIMING_C141.md) was rerun for its 999,002-vertex, 60-second Source cohort: 400 requested motion events per second, 64 CSS-pixel radius, 0.25 intensity, fixed topology, and no alpha, mirror, clay, accumulation or fold guard. The browser delivered 728 pointer moves and applied 658 dabs. The queued geometry timer includes 26,889.9 ms total work; its substage totals are 11,551.9 ms preparation, 15,334.4 ms deformation, and 3.6 ms other measured time. Per dab, these average **40.866 / 17.556 / 23.305 / 0.005 ms** respectively. The stage counters measure synchronous WASM work only; they exclude input delivery, uploads, drawing, GPU completion, and input-to-photon time. They do not by themselves predict WebGPU speed.

The independent whole-project and history audit passed, including 40,610 changed original vertices, finite useful deformation, zero new degenerate faces and zero original-face orientation reversals. Four frozen responsiveness gates failed: independent RAF P95 93.0 ms exceeded 33.34 ms; RAF maximum 403.8 ms exceeded 250 ms; summed app-frame CPU P95 92.6 ms exceeded 16.667 ms; and the observed release queue did not empty by 100 ms. The result is a bottleneck measurement, **not** SculptGL or ZBrush performance parity.

A separate C143 candidate skipped mixed face dispatch when every face matched the history topology. It passed the focused equivalence test, workspace tests, strict native/WASM Clippy, web build and macOS packaging, then ran the same frozen browser cohort. It applied 658 dabs but delivered 720 moves, with mean queued geometry/preparation/deformation of **40.840 / 17.533 / 23.301 ms**. Frame CPU P95 remained 92.6 ms, independent RAF P95 remained 93.0 ms, and the same four gates failed. Different delivered contacts and a 0.026 ms mean difference do not justify a speedup claim. The branch was removed; the final app WASM hash again matches C142. Both complete runtime files, whole-model audits, build hashes and failed checks are retained in [the C142 evidence](evidence/sculptgl-source-stage-c142.json).

The existing offscreen WebGPU point pass has different brush mathematics. A useful production GPU path must connect actual pointer picking, deform, normals, draw, document revision and Undo/Redo without full-mesh CPU readback per dab, while retaining bounded validation and native/browser behavior. The frozen million-vertex matrix and matched SculptGL response/performance comparisons must then be rerun. Physical pen, native GUI, arbitrary imported meshes and ZBrush 2026.2.1 remain unverified.
