## Diagnostic hypothesis, not an established outcome

At DPR 2 C307 observed `canvas.width,height=1600,1000` despite a 1600×1000 CSS canvas and 3200×2000 CDP screenshot. eframe 0.33.3 computes egui point extent as `canvas.width/(zoom*DPR)`, but `pos_from_mouse_event` maps CSS `clientX` to egui points by zoom alone. A visible pixel at CSS x≈345 may therefore be drawn by a control at egui x≈173 while a real click is delivered as egui x≈345. Its ResizeObserver may have supplied a backing size inconsistent with emulated DPR. The browser also could be failing to complete an otherwise requested download. C312 must distinguish these.

## Frozen probes and gates

1. At each DPR, capture before/after screenshots, CSS canvas rect and `clientWidth/Height`, `width/height`, `devicePixelRatio`, zoom, egui camera viewport, and OBrush message/dirty/history/selection. Record every dispatched client coordinate. On the normal visible Save button, use a screenshot-selected **visual** CSS coordinate, independently fixed before reading the outcome; C307 used (345,26) at DPR 1 and (345,45) at DPR 2. Record capture-phase `pointerdown`/`mousedown`, `click`, `keydown`, file chooser events, `obrushDownload` calls, CDP download begin/progress, and the post-click message/dirty state. Wait at most 5 seconds for app activation and 15 seconds for a completed download. Never report only a timeout. A visible click passes only when the download completes and app says `Download requested: ...`; if no app activation, classify input miss; if app requested but no CDP completion, classify host download failure; if app reports an error, classify save failure. A separate diagnostic click at half the visual x is allowed **only in a fresh page** and cannot pass the visible UI gate.
2. On fresh imported pages at DPR 1/2, select OBrush Source resolution via visible slider only. Capture its reported egui hit rectangle and screenshot visual coordinate separately. Require exact `viewport_resolution_scale` values 1, 0.5, 2, then exact 1 on return; a value such as 0.98 fails. Compare actual texture/depth allocations with reported scene target, reference backing at 1/.5/2, screenshot hashes, no GL/scene errors, unchanged history/selection, and byte-identical `.obrush` saves at every ratio. Retain partial measurements if an earlier gate fails. Do not smooth or change thresholds after seeing values.
3. At DPR 1/2 use a fixed visible scene CSS location, capture hover/away screenshots and the read-only cursor/brush metrics. Require a brush-circle CSS radius within 2 CSS px across DPR and actual nonzero pixels in the screenshot difference; no detected circle fails. Test a real mouse and CDP pen pointer (pressure 0.5) on separate fresh imports, with one short Draw dab at the fixed visible location (radius 0.18, strength 35%, symmetry off). Record browser CSS/egui/backing point mapping, scene pick, history and geometry revision and after screenshot. A pen event that is unsupported by the automation runtime is unverified, never a pass. Require mouse/pen contact and hover at the intended visible location within 2 CSS px and no spurious sculpt at an offset; if the read-only metrics cannot establish location, leave this gate unverified.
4. Product correction, if any, is a separate commit confined to the OBrush web host. It must make canvas backing equal rounded CSS extent×DPR (within 1 px) at DPR 1/2 without exceeding a 8192-pixel side or 16-million-pixel budget; preserve egui visible-control hit alignment, Source target sizing, picking, hover, pen input and document bytes. An unsupported or oversize viewport must fail explicitly rather than silently change geometry resolution. Run the same frozen harness against baseline and candidate; promote only if all subgates pass. No eframe vendoring.

Retain failed checks and exact receipts. This experiment cannot establish overall SculptGL or ZBrush parity.
