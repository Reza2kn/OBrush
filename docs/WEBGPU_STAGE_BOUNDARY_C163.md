# C163: WebGPU point/normal versus presentation boundary

The opt-in `?webgpu-preview=1&webgpu-depth-pick=1&webgpu-profile-stages=1` path now reports the synchronous cost of `present()` separately from the fence that waits for its submitted draw. This is diagnostic only. The ordinary studio still sculpts in Rust/WASM and draws with WebGL2.

The normal browser imported the independently authored 999,002-vertex / 1,998,000-triangle sphere, SHA-256 `dfb5316f62e392e633f03cb662dcb12215ed165a71a9ae72a3fd639528731afe`. A trusted three-contact mouse stroke used the existing depth-pick Inflate prototype. The baseline run, `.artifacts/gpu-pointer-c146/c163-depth-profile-r0/result.json` (SHA-256 `77a94aab7c0b8964051bb13a935407f4d9697182a7a718845ea43e99c166a8e3`), recorded 190.3 ms total fenced point/normal work, 19.0 ms fenced draw work, and 0.3 ms synchronous `present()` calls. The checked shared-core release took 435.8 ms, of which 430.9 ms was commit. Its detailed commit counters include 122.8 ms source matching, 124.8 ms fold guard and 176.7 ms document replacement. These are browser wall times for one profile, not isolated shader timings or a sustained distribution. The profiler inserts an extra fence after each point pass, so its totals must not be read as ordinary-stroke frame times.

An experimental face-row sentinel removed the second selected-face topology lookup. Three trial builds failed browser WGSL validation or bind-group layout checks, preserved as `c163-depth-sentinel-r1/r2/r3/result.json`. The corrected trial `c163-depth-sentinel-r4/result.json` (SHA-256 `118faa591cc3ef45d543a671c495f23156f3bcfd1364b47c7e877d4d83fbbd09`) passed the same browser edit and exact visible Undo/Redo checks. Both accepted runs changed 5,765 vertices and had the same before/after viewport PNG hashes, `5398141e2042c211dcd70ad09f7796b918381a54c29269fe89fc43a3ddf7903b` and `82b9fff7145e9ac0a930a21539cc1573d675ed97d2e92377cb8a0dab990c6d5b`. The trial measured 186.2 ms point/normal, 17.9 ms draw fence and 0.5 ms synchronous presentation. Single runs with browser scheduling and distinct release timings cannot support a speedup claim. The sentinel was removed, restoring the original geometry shaders and bind groups. A final restored-build browser run, `c163-depth-final-r5/result.json` (SHA-256 `4cde14f0b74474753881cd8333d556f361b9fb57add0f2639429afa0458dd8d5`), again passed the exact images and Undo/Redo with 190.3 ms point/normal, 17.8 ms draw fence, and 0.3 ms synchronous presentation. Its GPU WASM SHA-256 is `3dbf771e99b3a81edc625cb2490e2c4d51145d468f779a8920d81250cbc09c5a`; pointer host SHA-256 is `b48ec4c603a3f24c945bf4d48cb3da56676caa55e1ffdde6048a7a748677ccdc`.

The useful boundary is that removing browser calls around `present()` cannot by itself solve the million-vertex stroke. The current full-mesh point/normal passes and the checked document release remain the dominant measured work. A credible improvement needs a changed GPU work/ownership design and the unchanged sustained responsiveness and exact-history checks, rather than another micro-optimization of the presentation call. No SculptGL or ZBrush parity status is promoted.
