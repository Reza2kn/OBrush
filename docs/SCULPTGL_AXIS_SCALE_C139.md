# C139 selected world-axis scale foundation

OBRush now exposes independent positive world-X, Y and Z scale fields in the Transform panel. The shared Rust core accepts one selected-group axis-scale transaction around a world pivot. Whole-part mode carries posed affine matrices and retained editable state through the existing transform path; **Respect vertex masks** instead commits each selected vertex by its source unprotected weight, preserving protected coordinates and the imported affine pose. Invalid factors and candidate geometry are rejected before replacing the document. Undo/Redo covers the group as one edit.

An independently authored posed two-part SGL core fixture exercises both paths with factors `(1.2, 0.8, 1.05)` and a nonzero world pivot. An independent world-coordinate calculation checks every point, retained masks/faces/poses and exact serialized history. In the normal browser, two selected patterned spheres use the visible axis-scale numeric controls and mask option. Against a separate scalar oracle, the maximum saved point-component error is `2.4614555860225096e-7`; 76 fully protected points remain exact, 380 partially protected points are present, and 456 points change. The rebuilt browser passed 13 transform workflows with exact history, saved/GPU agreement, no JS/GL errors and actual 4× MSAA.

The pinned SculptGL runtime was also checked on the same independent `#MAT` OBJ cube used in C138. Its actual `Transform.end()` kernel received a controlled diagonal edit matrix for `(1.2, 0.8, 1.05)`; SculptGL and OBrush each imported through their normal browser file input and used their normal Undo/Redo routes. After the previously recorded unique-position vertex mapping, the maximum OBrush-versus-SculptGL output-component difference is `5.287933357855934e-8`; input positions match exactly and unprotected weights differ by at most `2.0984268211954316e-8`. Both preserve the one protected point and six partially protected points. [The evidence](evidence/sculptgl-axis-scale-c139.json) records the reference/build hashes, exact controls, raw results and failed-check history.

This establishes **numeric world-axis scale on scoped fixtures**, not SculptGL's axis-scale gizmo parity. The reference edit matrix came from the diagnostic, not a physical scale-handle drag. OBrush does not yet preview or drag the source's X/Y/Z scale cubes or uniform ring; mixed numeric transform fields currently require separate applications. Broader geometry, source-native poses, retained masked detail, large deformations, visual normals, native GUI input and sustained performance remain open. ZBrush desktop 2026.2.1 remains the longer-term target.
