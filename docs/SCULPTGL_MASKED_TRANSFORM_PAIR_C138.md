# C138 paired pinned-runtime masked transforms

This run moves the C136–C137 mask-weighted transform comparison from source-code inference to a measured pinned SculptGL runtime. An independently authored eight-vertex OBJ cube with `#MAT` unprotected weights was loaded through SculptGL's ordinary file input and OBrush's ordinary browser import. SculptGL's Transform tool was selected through its normal UI; a diagnostic then installed two controlled edit matrices and invoked the pinned `Transform.end()` kernel. Its Undo and Redo buttons restored exact saved mesh states. OBrush used its visible **Respect vertex masks** option and numeric Transform controls on the same OBJ; its saved `.obrush` projects and keyboard history were checked in a separately owned browser.

The importers order the cube vertices differently, so the comparison first matched all eight unique unchanged input positions by coordinate. This yielded the explicit SculptGL-to-OBRush index map `[0,7,3,4,5,1,2,6]`. All mapped input positions agree exactly; the largest unprotected-weight difference is `2.0984268211954316e-8`. With world-X translation `+0.125`, the maximum mapped output-component difference is `4.7149658177758624e-8`. With world XYZ rotation `(7°, −3°, 5°)`, scale `1.05`, and translation `(0.02, −0.015, 0.01)`, it is `1.658187867015215e-7`. Both runs preserve the one fully protected vertex and include six partially protected vertices; OBrush project Undo/Redo and SculptGL mesh Undo/Redo are exact in these fixtures. The OBrush browser reports no JS/GL errors and actual 4× MSAA. The [evidence record](evidence/sculptgl-masked-transform-pair-c138.json) binds the pinned bundle, fixture, raw before/after outputs, mapping, harness and browser WASM hashes.

Three investigative failures are retained. A minified source constructor name invalidated the first reference diagnostic's class-name assertion. The first OBrush paired attempt assumed a v6 standalone OBJ import must carry a scene object. The next assumed the two importers preserved identical vertex indices; the raw differences exposed the ordering mismatch. Each diagnostic was corrected without changing either application's transformation code.

The unchanged C137 Rust/browser build (`00bf0e27b5cb64c658764c6117577e7193dcbc701e9331cdbce2f5e04602423e`) also passed a fresh complete twelve-workflow browser regression after the paired harness was added. C137's workspace tests, strict native/WASM Clippy and signed macOS package remain the source-validation receipt; C138 changed only diagnostic scripts and documentation. Both diagnostic scripts pass Node syntax checks.

This is **one paired kernel and browser UI fixture**, not full SculptGL Transform parity. The reference edit matrices came from the diagnostic, not physical gizmo drags. The source and OBrush browser hosts were separate isolated Chrome runs; native GUI, multi-selection, posed source meshes, retained detail, nonuniform scale, other handles, all-protected center movement and sustained latency remain unpaired. ZBrush desktop 2026.2.1 remains the longer-term target.
