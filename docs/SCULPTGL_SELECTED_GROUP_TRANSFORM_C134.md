# C134 selected-group numeric transform

OBRush's numeric Transform panel previously applied only to the active part, even when the scene panel held a multi-selection. `Document::transform_selected_subtools` now applies one shared world transform to every selected object. The operation builds and validates a detached candidate, then commits one history entry; a later selected object that fails validation cannot leave earlier objects partially transformed. Selection order and active identity survive the commit. The panel's **Selection center** pivot is the mean of the selected objects' world centers, including source affine poses. The existing active-only interactive gizmo is unchanged.

The shared-core fixture imports the independently authored 540-byte posed two-mesh SGL (`99e107226fd5bdfeb687a4d92a61eebcec1abb2e910184e35aa58808ace105fd`), selects both parts, and applies `(0.25, -0.125, 0.5)` world translation. Each sampled world point moves within `1e-6` of that vector; the mean selection pivot is within `1e-6` of the two separate world centers. One Undo and Redo restore exact versioned project JSON. A second fixture puts one selected sphere at the world-coordinate bound: failure on that later member leaves the earlier member, selection, saved project and history unchanged. Invalid and identity requests also preserve the project.

The normal OBrush browser route imports the posed SGL, Ctrl-clicks the other part in the scene panel, enters `0.25` in the numeric world-X field, clicks Apply, then uses normal keyboard Undo/Redo. The built WASM SHA-256 is `05d0e2b1c9be4fb60a063896d89526cb1b545d17bb2b83fcb7808c44a7047e31`. Both serialized `scene_v7` affine matrices gain exactly `0.25` in the X translation slot, with zero maximum element error; local active/inactive meshes and source origins are unchanged. The document revision advances once, selected IDs and active ID persist, and saved project SHA-256 goes from `7806128a01d641f774943b3a708ce8afa9f9db7df8330bfa5336f84b4800542b` to `76b898ab1c396e767faad0d4c82333235358aa0df975beb7cb73406d50e5be3e`. Undo and Redo restore those hashes exactly. The raw run and intermediate failure records are under `.artifacts/scene-group-transform-c134/`; the [machine-readable receipt](evidence/sculptgl-selected-group-transform-c134.json) binds the final run and checks.

The first browser driver attempts failed because the inspector scrolls to keep a focused numeric field visible. Reusing its old screen rectangle clicked world Z, and reusing an old Apply rectangle clicked elsewhere; an early Undo then undid the import. The final driver reacquires each rendered rectangle after focus/scroll and verifies the actual entered X value before Apply. Those failures are retained and are not counted as geometry regressions.

This is an OBrush numeric group-transform foundation, **not** SculptGL transform parity. The pinned source's group gizmo operates with interactive axis/plane/rotation/scale handles and mask-weighted vertex commits. The current OBrush gizmo remains active-only; the browser run did not drive the pinned source, compare masked transforms, test nonuniform/plane/view handles, or measure sustained latency. Native GUI interaction remains untested.

Final `cargo fmt --all --check`, workspace/all-target tests (100 summaries; **2,462 passed, zero failed, one ignored**), strict native and WASM Clippy, `scripts/build-web.sh` and `scripts/package-macos.sh` passed. The ad-hoc-signed app passed `codesign --verify --deep --strict`; its executable SHA-256 is `0872266316b7ea59ad8e6e070192b0399c6a7093890e7fc3ae5b7b5e91612d2d`. The existing single-part browser transform harness passed all eight workflow cases against the same WASM hash, including numeric rich-state transforms, gizmo preview/commit, exact Undo/Redo, and legacy project versions. These checks do not substitute for the missing pinned-source group-gizmo comparison.
