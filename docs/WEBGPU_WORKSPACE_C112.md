# C112: resident GPU code in the current workspace

The independently written `wgpu` 27 residency prototype is now the `obrush-gpu` workspace crate. Its bounded, GPU-independent point input and selected-normal scalar reference live in `obrush-core` and compile for native Rust and WASM. The GPU crate keeps the native Metal/browser WebGPU compute, current-surface ray picking, conservative bounds rebasing and indexed canvas drawing behind its own resource ownership. Cargo.lock retains the wasm-bindgen `0.2.129` pairing. CI checks the GPU crate's WASM target alongside the delivered app.

This is an integration foundation, **not a renderer switch**. The OBrush studio still uses Rust/WASM CPU geometry and WebGL2 drawing. The GPU point operation does not implement the production Source Inflate brush's contact selection, mask/alpha/fold semantics, document/history transaction or multi-subtool picking. Its speed cannot be substituted for the existing failed million-vertex 60/120-second consumer responsiveness gates.

The [C112 evidence](evidence/sculptgl-webgpu-workspace-c112.json) records the root-workspace build and an owned Chrome run on the unchanged independently authored 999,002-vertex / 1,998,000-triangle SGL fixture (SHA-256 `dfb5316f62e392e633f03cb662dcb12215ed165a71a9ae72a3fd639528731afe`). The browser used the newly built workspace GPU WASM (SHA-256 `a53bc6d4bf77b4be3d37d6371763bf051c5db1ae9a377c1e27a534120a614ed7`), not the frozen staged binary. It ran 32 point passes, presented perspective and orthographic 512×512 frames, and queried six named rays. Four visible hits matched a **new native Metal run from the current workspace** in face ID, f64 distance and f32 position; two background rays missed on both. Both complete RGBA images matched pixel-for-pixel. The new native result equals the frozen C65 result except for the expected source-camera file label changing from `source/crates/...` to `crates/...`; an initial whole-file byte comparison failed on that label and is retained as a failed check.

The actual browser WebGPU trace shows four 5,994,000-index draws and seven 8-byte pick-result maps after the first presentation marker, with no whole-mesh map in that interval. An invalid camera matrix and mismatched extent were rejected without altering the previous screenshot. A valid 960×540 resize was presented and picked. No GPU validation errors were reported; the owned Chrome process exited with code zero and its loopback server closed. These counts describe this probe's GPU submissions and diagnostic observations, not physical input-to-display latency.

The final source passed `cargo fmt --all -- --check`, all 2,431 workspace tests, strict native workspace Clippy, strict WASM Clippy for core and GPU, WASM app/GPU checks, the official `scripts/build-web.sh` and `scripts/package-macos.sh`. The normal studio browser passed six scoped Reverse cases, 36 actual downloads and 36 GPU/save checks after promotion. Its WASM SHA-256 is `7046684c99f3af5bbc689d2f7bf29541c5fc67cdac7389bd32fac4e7dbcdb4b1`. The macOS package has a valid local signature.

The next product gate is a validated document/stroke owner that can keep a current mesh on the GPU through real brush selection, deformation, normals and presentation while preserving CPU fallback, undo/cancel/save, imports, subtool transforms and device-loss behavior. Only then can the unchanged 60/120-second browser matrix and pinned SculptGL brush comparisons establish a real performance or parity improvement.
