# MRP10: bounded persistent Source Worker trial

This is a small architectural candidate for the existing query-gated, off-by-default Source Worker trial, based on root `b8ce3a5`. A successful held gesture currently destroys its Worker and the next gesture instantiates and initializes another WASM realm. Reuse the same idle Worker after a **successfully checked final commit** only. Each gesture still transfers a fresh public project and retained packet, starts a new core Source transaction, and must pass the existing complete-scene, delta, retained-state, history and GPU checks. A rejected, cancelled, crashed, disabled or stale gesture must terminate the Worker. No geometry or packet validation may be relaxed. Worker message sequence resets to one only at a new accepted `begin`; epoch, ID and outstanding-message checks remain.

This cannot by itself resolve the measured 100k final main-thread commit (~475 ms) or million-vertex initial project serialization. It is a scoped Worker lifecycle step, not admission to the million-vertex responsiveness gate. Before any speed claim, run an owned normal-browser matched control/candidate with the independent 999,002-vertex SGL fixture SHA-256 `dfb5316f62e392e633f03cb662dcb12215ed165a71a9ae72a3fd639528731afe`, same 60-second/400-requested-moves/s protocol SHA-256 `234870ed03a240931a22f421968917efaeed8becc1a2df742bd25f29d`, and all four unchanged thresholds: active RAF P95 <=33.34 ms, RAF max <=250 ms, app callback CPU P95 <=16.667 ms, release acknowledgment <=100 ms. The final Worker queue must be empty by 100 ms after release. Do not infer a speedup from a few gestures or a worker-start microbenchmark.

First run deterministic JS lifecycle checks for two consecutive committed strokes (one Worker, two distinct epochs, fresh begin, reset per-stroke sequence, exact release endpoint), cancellation/rejection after a committed stroke (no publication, Worker termination), disable/reenable (new Worker), late reply rejection and no post-release dabs. Run `cargo fmt --all -- --check`, workspace tests and strict native/WASM Clippy if Rust changes occur; run the official web build and a normal browser after JS Worker/host changes. Preserve failed results.

For any browser promotion, independently compare Before/After/Stable/Undo/Redo public project bytes and all changed position/normal words, affected-face degeneration/orientation, checked retained-state report, and actual GPU VBO position and Source display-normal f32 words. Saved mesh normals are not an edited Source display-normal oracle. Require one history step, exact endpoint, bounded Worker count and clean shutdown. The experiment remains query-gated if any exactness, error, memory or timing gate fails.
