# C133: selected-part Merge with posed SGL inputs

The existing OBrush Merge control required a separate checklist and rejected every imported SGL part carrying editable pose or source-origin metadata. The normal scene panel now also has **Merge selected**, using the actual multi-selection. The shared Rust merge concatenates displayed surfaces in selection order, appends the result after unselected parts, and retains the selected active ID as SculptGL does. It bakes each selected affine pose to world coordinates before concatenation. The explicit `SubtoolMergeSettings` loss flags control source-pose/provenance loss, mask-convention rounding and UV detachment; rejection occurs before mutation. The browser action declares these losses in its hover text and reports their counts after completion. One Undo restores the complete originals.

The first independent fixture is the three closed boxes from C130 (1,560 bytes; SHA-256 `939110d73dec934f0af70fb5c364eeb18f3ce18608449fe76804896c50c9c0ae`). Under pinned SculptGL revision `8e45dafc0f7906e5238dfffc1a2df742bd25f29d`, physical Shift-clicks select right and center boxes in that order, then its GUI Merge handler leaves the unselected left box and one 16-vertex/12-quad result. OBrush imports the same bytes, selects right and center using the normal scene-panel Ctrl-clicks, and its visible Merge selected button leaves the same two-part scene. The selected right original ID remains the result's ID in each application. The source and OBrush use different vertex-array order after source `MeshStatic.init`; their **world-position sets and oriented world-face multisets match exactly**, all 16 positions and 12 quads. Per-position RGB differs by at most `2.384185793236071e-8`; the first two material channels match exactly. OBrush's 7,778-byte pre-merge project SHA-256 `2536cb091e14340b8d48b7f76656b0985ae849f165403f3dd40b98ba0bf94628` changes to the 4,800-byte merge SHA-256 `cd43f58ec2b4b1367b5e7d281b29e4401cb819ddfa570a0899d1f2599c90167a`; ordinary Undo/Redo restore each hash exactly.

The second independent fixture is a posed two-mesh SGL (540 bytes; SHA-256 `99e107226fd5bdfeb687a4d92a61eebcec1abb2e910184e35aa58808ace105fd`). The pinned source selects its other object through the application selection method, merges, then Undoes and Redoes. OBrush uses a normal scene-panel Ctrl-click and Merge selected. The resulting seven **indexed world positions and two oriented polygons match exactly**; the polygon pair triangulates into three triangles in OBrush. Indexed RGB matches exactly; the largest difference in the first two material components is `7.152557379708213e-9`. OBrush's 3,133-byte pre-merge project SHA-256 `7806128a01d641f774943b3a708ce8afa9f9db7df8330bfa5336f84b4800542b` and 1,086-byte merged SHA-256 `81a481d12111ce87bbb961f03bc155433b40e44115774e8b912e6dae0efe93fa` recover exactly through Undo/Redo. The shared-core test independently confirms posed world coordinates and that three mask f32 words would change on roundtrip between conventions; refusing any required loss leaves the full project unchanged. With explicit loss flags, the normal browser reports two baked poses, one UV-bearing part detached, and three mask values rounded.

The [machine-readable paired comparator](evidence/sculptgl-selected-merge-c133.json) is reproducible with [compare-selected-merge.py](../scripts/compare-selected-merge.py) and retains exact raw browser-result paths and hashes. Current-build regression reruns of selected-group Delete, Duplicate, Isolate/Show all and the SculptGL-profile keyboard route all pass after the selection-active policy correction. The source's Undo may reorder original objects; OBrush restores its exact pre-merge project instead. SculptGL's third material channel, masks after its static merge, varied UV seams/materials, hidden-part merge policy, native GUI interaction and sustained performance remain open. These two fixtures do not establish the complete SculptGL Merge gate.

Two initial posed-fixture source runs timed out because the harness still waited for three meshes after switching to a two-mesh fixture; the source already contained two. The corrected run passed. The first Rust posed-merge checks failed on mixed mask conventions and then mixed UV presence; those failures led to explicit loss flags and atomic rejection checks. An existing scene-order test then failed because the result is now appended as in SculptGL; its expected order was updated without weakening its unselected-part identity and attribute assertions. The failed source records and follow-up checks remain retained in `.artifacts/scene-merge-c133/`.

Final `cargo fmt --all --check`, 100 workspace/all-target test-result summaries (**2,460 passed, zero failed, one ignored**), strict native and WASM Clippy, and `scripts/build-web.sh` passed.
