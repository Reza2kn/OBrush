# C268 preregistration: bounded shared pages for Source face bounds

This isolated shared-core trial starts from `d13eb29ac68747e494ad312cd010e41990ddb5b0`. The frozen C264 browser baseline is `999,002` vertices, `1,998,000` original faces, 957 delivered Source dabs, `7.116 ms` mean state-advance, `66.7 ms` active RAF P95, `159.0 ms` release acknowledgment, and 0/4 responsiveness gates. The C265/C266 renderer trials and C264 normal-scratch trial were rejected. The independent C267 one-pass rollback-copy experiment has at most a `0.400 ms` old-copy stage ceiling and is not a responsiveness solution.

`OrderedTree::copy_fallible` currently copies every face-bound row on each accepted local refresh. This trial replaces only its private flat face-box array with fixed-size, 2,048-row copy-on-write pages. A new tree initially shares unchanged pages with its predecessor; the refresh copies only pages containing affected face rows before writing their exact f32 bounds. Face order, f32 words, cell topology, leaf membership, selection, balances, incident rings and renderer data remain unchanged. Each state continues to charge every page's full storage, including page/Arc overhead, even when physically shared; allocation is fallible before publication and subject to the existing ordered-tree cap. Rebuilds construct fresh pages. No external file format or history change is intended.

Admission requires an exact oracle comparing old flat and paged tree snapshots across independently authored local motion, leaf crossing, root escape/rebuild, balanced end, zero-area and repeated warm dabs. Preserve f32 bits including signed zero, ordered IDs, ABA handles, and atomic failure behavior. The bounded page metadata consumes additional charged bytes, so a mesh at the old storage boundary may now reject; record that boundary rather than claiming unchanged admission. Run focused tests and the ignored `million_face_flat_copy_vs_local_paged_refresh` microbenchmark alone before broad checks. That diagnostic uses 1,998,000 authored bounds, 20 rounds and 100 local changed faces per round; preregistered direct-copy target is paged local total below one quarter of the full flat-copy total. This is a storage-substage diagnostic, not a measured Source dab or browser responsiveness result. Reject if exact words fail or this direct-copy target fails. If those pass, run `cargo fmt --all -- --check`, full workspace tests, strict native/WASM Clippy and `scripts/build-web.sh` after the shared build lane is released. A frozen browser run is warranted only if the focused evidence supports it; it must retain the C264 fixture/protocol hashes, independent Save/Undo/Redo audit and every responsiveness gate. Different delivered dab counts forbid causal browser speedup claims.

## Focused result, before admission

In the isolated worktree, `cargo fmt --all -- --check` passed. The paged/complete-flat-copy oracle, all-page copy/storage test and multi-page warm decode plus later refresh test passed; `cargo test -p obrush-core --lib face_box` also passed with the ignored diagnostic excluded. The ignored 1,998,000-row, 20-round debug-build diagnostic reported `697.292167 ms` total for complete flat copies and `394.209 µs` for 100-row paged local refresh copies. The preregistered storage-substage threshold passed, but this is neither an optimized whole-tree benchmark nor a whole Source dab measurement. The candidate source SHA-256 values are `ea4a02e15542a5ce214f3a2d09603d971a167d5acf46d73147b43dec1e82d1fb` for `source_ordered_tree.rs` and `8af760492a7d4a13e1c2aa39c4bbc2fb1a1de8fb2c5d1d2ea706c85577b07306` for the warm codec. Full workspace tests, strict native workspace/all-target Clippy, strict WASM core Clippy and `scripts/build-web.sh` all subsequently passed.
