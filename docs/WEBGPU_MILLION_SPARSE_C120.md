# C120: million-vertex GPU sparse capacity check

The C119 GPU-owned changed-row path now has a capacity check on the unchanged independently authored SculptGL SGL3 fixture: **999,002 vertices / 1,998,000 triangles**, SHA-256 `dfb5316f62e392e633f03cb662dcb12215ed165a71a9ae72a3fd639528731afe`. One diagnostic resident point pass uses local center `[0,0,1]`, radius `0.5`, intensity `0.25`, no symmetry, and an owned GPU checkpoint.

Native Metal produced **41,065 changed vertices / 821,300 sparse bytes**. The sorted compact output matches a reconstruction from every changed row of the complete **15,984,032-byte** GPU position buffer exactly. Browser WebGPU returned the identical sparse SHA-256 `5d01e205c078e90b1673f3404f453cee7ecb0a436fea9f8d7e19ffbe99757b88` on the same fixture and parameters. Its actual GPU trace maps `[4,4,821300,4]` bytes for the failure word, changed count, compact result and post-collection count, with **zero full-position readbacks**. The GPU owner reports 241,857,652 resident bytes inside its 256 MiB cap, no device errors, and a clean owned-browser exit/server closure.

The native one-shot observations were 6.72 ms for sparse count/compaction/readback/sort and 25.62 ms for a later full readback. The browser's one-shot sparse observation was 5.80 ms. These are **not controlled speed ratios**: the operations ran in different orders and warm states; they exclude normal-studio input, document validation/commit, history, brush selection, renderer work, device loss and sustained strokes. The point program does not reproduce SculptGL's brush response. In particular, the normal OBrush browser still uses CPU/WASM geometry and WebGL2; its failed million-vertex sustained responsiveness gate is unchanged.

The new native diagnostic is `resident_sparse_capacity`. The full-workspace checks, exact source/build/output hashes and browser trace are recorded in [evidence](evidence/sculptgl-webgpu-million-sparse-c120.json); raw outputs stay in ignored `.artifacts/gpu-capacity-c120/`. This result supports the next integration step: connect a validated live studio stroke to a resident GPU owner, then rerun the original browser responsiveness matrix without changing its thresholds.
