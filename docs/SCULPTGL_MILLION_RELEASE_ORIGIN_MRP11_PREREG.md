# MRP11: ordinary million-vertex release provenance gate

The unmodified Source release core in current root `55aa53a` is byte-identical to the MRP03 base `30a7e7a`. MRP03's independent 999,002-vertex SGL browser stroke recorded 75.7 ms in `end_source_geometry_stroke_timed`: 19.7 ms validation, 1.2 ms history, 10.1 ms balance and 44.7 ms finalization. The complete released frame was 103.6 ms in the app, while the frozen release-command acknowledgment was 159.97 ms. These are a single prior browser observation, not a current matched candidate/control. Before an implementation, inspect a fresh current ordinary browser control and retain its `release_timing`, queue metrics, public five-state files, and GPU words.

Candidate: remove repeated full scans of **immutable original SGL provenance** at Source release only, using a bounded `Document`-owned proof that holds a strong `Arc<SglMesh>` and its exact version, validated triangle count and storage count. Acquire a proof only after full `sgl::validate_mesh` success on import or public JSON load. Because the proof holds a strong Arc, safe Rust `Arc::get_mut` cannot change its raw data; `Arc::make_mut` changes identity and must cause full revalidation. Do not cache an editable `Mesh`, affine, render setting, scene structure, header, retained Source normal state, or history. Require exact Arc/version match for every use; new/missing/stale origins fall back to full validation. Keep public project validation, output/storage limits, complete scene and history checks. Limit proof entries to `MAX_SUBTOOLS` with no copied vertex/face arrays; no global pointer-only cache.

First prove with core fixtures: successful imported Source stroke/Undo/Redo public bytes and retained-state words are identical to the uncached path; no-op preserves redo; direct editable mesh mutation is still rejected; an external `Arc::make_mut` raw origin change cannot reuse proof; stale version/identity and malicious malformed origin are rejected; inactive multi-object aggregate counts and overflow semantics are unchanged. The exact 999,002-vertex public project and prior 1m receipt hashes must be pinned before any browser run. Do not edit product code if the proof cannot be made sound under the current `Document` API.

Run a bounded same-state native core comparison first with the public million-vertex fixture and identical stroke stream, five alternating control/candidate repetitions, source release substage timers, exact public mesh/history words, and peak RSS. Admit a browser candidate only for a median >=15 ms release total reduction, >=10 ms finalization reduction, no >16 MiB peak RSS increase, and exact words/errors. If the native gate fails, stop early and preserve it. Browser comparison then uses the unchanged frozen 60-second, 400-requested-moves/s ordinary protocol (`234870ed03a240931a22f421968917efaeed8becc1df834c998bbe3e9c101a33`) and independent million SGL fixture (`dfb5316f62e392e633f03cb662dcb12215ed165a71a9ae72a3fd639528731afe`). Use separate owned Chrome profiles, hash all builds and runners, retain failures and cleanup status. Require independent 17-check Before/After/Stable/Undo/Redo and affected-face audit, exact history, finite geometry, and actual GPU position and Source display-normal f32 words. Public mesh normals are not a display-normal oracle.

Report all four frozen responsiveness thresholds separately: RAF P95 <=33.34 ms, RAF max <=250 ms, app CPU P95 <=16.667 ms, release acknowledgment <=100 ms. A release-only improvement cannot close press, first-dab and steady-stroke failures; it never establishes SculptGL or ZBrush parity. Do not promote the candidate to the ordinary path unless the exactness and memory gates pass.
