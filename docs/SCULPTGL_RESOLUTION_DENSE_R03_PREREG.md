# Resolution-stroke R03 preregistration: dense independent sphere

**Proposed, unrun; `SGL-RENDER-RESOLUTION` remains Open.** R02's one held
12-CSS-pixel Draw move changed only one position word per app. R03 repeats
the same paired normal-browser route on a dense, independently generated
closed sphere, and requires a useful deformation footprint before any
invariance claim. The R02 and failed C327 receipts remain unchanged.

## Frozen material and route

- Reference: pinned SculptGL commit
  `8e45dafc0f7906e5238dfffc1a2df742bd25f29d`, bundle SHA-256
  `79b24bf6e1818cbb468c53cfe49783de419fd3e58f72b220aeb9308932e47600`,
  mirror wrapper SHA-256
  `a87cc1246a6bc39cebf81b78dcf6d6c5c6201ef72710dab7f177d1fe4acd11f0`.
  Record the exact official OBrush product revision and portable WASM SHA-256
  before browser measurements.
- Fixture: `independent-resolution-dense-r03.obj` generated by
  `scripts/generate-independent-resolution-sphere-r03.py`. It contains
  18,242 independently written vertices and 36,480 outward-wound triangles,
  signed volume 4.186921, 1,383,168 bytes, SHA-256
  `492dd0cfa56544bab0e816efa68a4b48b522ddaf5c70cbb2f95b6c92d167ec2e`.
  Regeneration must reproduce the same bytes. Both apps import it through
  the normal file chooser and select the imported sphere.
- Owned Chrome, 1600×1000 CSS viewport, 100% zoom. Run separate DPR 1 and
  DPR 2 sessions, each with fresh pages for resolution 1×, 0.5× and 2× in
  each app. Reference ratio changes may call the mirrored GUI controller
  because its topbar has no reliable visible hit target; OBrush must use
  its visible Source slider. No geometry API may modify either app.
- In each app, keep the same CSS start for all three ratios, at the measured
  viewport/canvas center. Send one trusted mouse press, wait 60 ms, move
  exactly +12 CSS px while held, wait 120 ms, and release. No replay/Undo
  reset. Reference brush remains Brush radius 50 px, intensity 0.5; OBrush
  remains Draw radius 0.18, strength 0.35. Do not equate these brush shapes.

## Acceptance fixed before execution

1. Require exact reference backing = CSS viewport × ratio (±1 px) and
   OBrush actual scene = CSS scene × ratio (±1 px) with matching WebGL
   color/depth allocation sizes. Record host canvas separately at each DPR.
   All GL/scene errors must be zero. Scene, selection, brush settings and
   history must be stable before contact; OBrush cursor-start error ≤2 CSS px.
2. One released stroke must increment history by exactly one and change
   **at least 24 distinct vertices** in each app at *each* ratio and DPR.
   Count distinct indices from position-component deltas >1e-10 model units.
   Smaller changes are an **uninformative failed gate**, not a pass. Record
   vertex count, changed-index hash, total/max displacement and other-object
   preservation where the public project allows it.
3. Within each app and DPR, 0.5× and 2× must have the same vertex count,
   identical changed-vertex IDs, and maximum post-stroke coordinate difference
   ≤1e-5 model units against 1×. Record actual maximum rather than rounding
   it away. OBrush's pre-contact public `.obrush` bytes must be identical
   across ratios, with selection and Undo stable; each resulting project
   must be valid and undoable. Reference history and selected mesh must be
   unchanged by resolution alone.
4. Preserve all failed or interrupted receipts. Do not promote from a
   source-controller route to full visible-UI parity. A product candidate
   requires a measured OBrush-specific discrepancy with the source control
   passing the corresponding gate. A passing R03 would still cover only
   this sphere, one short Draw move, two DPR values and one browser/GPU.

Long strokes, pressure, symmetry and masks, other tools, native GUI, browser
zoom, performance, exact cross-app brush shapes and full SculptGL/ZBrush
parity remain open.
