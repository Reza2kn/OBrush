# C273: Brush Lock Position stays open

This is the result of the prospective [Brush Lock normal-UI protocol](SCULPTGL_BRUSH_LOCK_UI_PREREG.md) for inventory row `SGL-BRUSH-BRUSH-LOCK`. The reference is pinned SculptGL commit `8e45dafc0f7906e5238dfffc1a2df742bd25f29d`, hosted JS SHA-256 `79b24bf6e1818cbb468c53cfe49783de419fd3e58f72b220aeb9308932e47600`. The independently authored RGB-ID sphere has 10,114 vertices, 20,224 triangles and SHA-256 `39ddfd1559fde94aa5f6d2602beffc6cf9f77fb7f934989ee9f8677739f47c1b`; the independent 16×16 hook-alpha PNG is 95 bytes, SHA-256 `0486e281eeb2766ecf096ef55fe42023545675d9d9bc123441cd729109ac290a`.

The current OBrush Source geometry mode does not offer Brush Lock Position and explicitly rejects a locked Source stroke. An isolated, reversible trial showed the control and routed Source-mode Draw to the existing shared-core `LockedStamp`, with Source intensity, Negative, Clay and Culling settings, and adaptive detail off. This trial was never promoted to the main checkout. Its exact patch is retained at `.artifacts/sculptgl-brush-lock-ui/isolated-locked-stamp-trial.patch` (SHA-256 `4fc279b628494933a240c8412e32192d8c436ecd4b90dd545b4f5a1b38d0c2e5`). It passed `cargo fmt --all --check`, `cargo test --workspace --locked`, strict native workspace Clippy and strict WASM workspace Clippy. An initial `scripts/build-web.sh` attempt failed because `CARGO_TARGET_DIR` pointed to a shared cache while the bindgen step reads a relative `target/` path; linking an ignored local `target` to that cache allowed the unchanged build script to complete. The isolated portable JS/WASM hashes were `9e20a578f57c85835ab2b983477df748461c1127674eddc5d1e3a42490f0dec1` / `3ba12cf9af7696d25f8715b5d5f14be5785804ffb58243f4aabc04487c2f9687`; SIMD JS/WASM were `9ca9ebdafe4dfb9cd4be96955e3ec7610d353306734c4951d0f9704569e411ea` / `42d13a9b1c26e53c894eb9f9dc5c30d1476efe6bebd20b06fc82c70b523d4d5b`.

Both applications were driven through their normal UI, with Source Brush/OBRush Draw, Clay/Accumulate/Negative/Culling/X symmetry/Continuous/Prevent folds off, no mask, orthographic front framing, radius 64 screen points, intensity 25%, pressure factors zero, and the same PNG alpha. The held path was press at center, +80 CSS X, -80 CSS Y, return to +80 CSS X, then release. The harness calibrated each application's pointer offsets to the same projected horizontal ray and radius: world-radius difference was `2.78e-17`, maximum recorded horizontal ray difference `5.55e-17`. The final paired harness SHA-256 was `867d2a03978b7b54175f8efc989e0a262d4585eb751468cc28a8e3baa05adc71`.

The paired **Before** geometry, faces, and attributes matched exactly. Each side had one reversible history step: public Before equaled Undo and After equaled Redo; every active GPU position stream matched its public Save positions, with unique/error-free active-draw identity. Both sides had no press dab, distinct rotated preview, exact repeated endpoint, release equal to the last preview, and stable quiet frames. The trial still failed the frozen geometry gate. SculptGL changed 26 RGB vertex IDs; OBrush changed 87, and their changed-ID sets differed. Paired **After** differed at 97 IDs / 291 XYZ components, maximum absolute component `0.0071530938148498535`, versus the preregistered `1e-6` threshold. Active GPU display normals differed at 146 IDs / 436 components, maximum `0.00018969192751683295`; this compares display GPU words, not saved normal fields. The held previews had the same position mismatch. The trial's first and second lock radii were `0.2883778214454651` and `0.29217228293418884`, failing the frozen equal-radius gate despite a stationary center and approximately quarter-turn alpha rotation. Differences in vertical viewport/projection handling may contribute to the radius result, but cannot qualify the observed paired geometry or changed-ID failure. The existing legacy `LockedStamp` path is therefore **not a Source Brush Lock implementation**.
