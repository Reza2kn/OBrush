# C191 plane translation gizmo

The normal OBrush Transform viewport now has three colored plane pads alongside its world-axis arrows, scale cubes and uniform ring. X, Y and Z pads constrain translation to the corresponding YZ, XZ and XY world planes. The handle starts a camera-frozen, absolute ray/plane drag: it records the pointer's initial offset from the projected pivot so grabbing any point inside a pad does not jump the part. A held drag previews through the render matrix without changing the mesh or document; release makes one shared-core selected-group translation transaction. The existing optional mask weighting, command barrier, cancellation and Undo/Redo semantics apply.

The implementation follows the plane selection and pointer-offset construction in pinned SculptGL `src/editing/Gizmo.js` at commit `8e45dafc0f7906e5238dfffc1a2df742bd25f29d` (file SHA-256 `e56a6e70f0eb2d53dd30240aa8a93c16258a3605b0a885aab743b6cb07df3c6c`). OBrush's pads use its own dimensions, projection and visual design. The Rust geometry test checks all three plane normals, a known projected target, chunk-invariant absolute motion and exact return to zero with a nonzero initial pointer offset.

The ordinary browser transform harness passed 17 workflows. Its independently authored two-part fixture used an actual Plane Z pointer drag with preview translation `[0.215165376663208, 0.1836179494857788, 0]`; the normal-axis component was exactly zero. Held VBO/IBO bytes and document revisions stayed unchanged. Release incremented the document revision once; the saved mesh matched independent affine position arithmetic within `5.960464477539063e-8` per point component, and Undo/Redo recovered exact serialized states. The browser run had no reported GL/JS runtime errors and recorded a quiet release. The local macOS app signature verified. The browser harness uses an owned isolated Chrome profile and synthetic pointer events; it did not touch the user's browser tab.

This is a source-derived gesture implementation and one normal-browser plane-pad interaction, not a paired physical SculptGL gizmo or visual comparison. Other camera poses, small or edge-on pad selection, selected-group plane gestures in the browser, rotation handles, native physical input, retained-detail mask transport and sustained large-mesh latency remain open. It does not establish Transform-family, SculptGL or ZBrush parity.
