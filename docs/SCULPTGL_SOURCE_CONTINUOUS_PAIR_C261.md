# Stationary Continuous Draw: paired browser check

The pinned SculptGL bundle and OBrush's normal browser UI were driven separately on the same independently generated 10,114-vertex, 20,224-triangle sphere. Draw used a 64-pixel radius, 0.25 intensity, zero pressure factors, no symmetry, and a stationary mouse hold requested for 400 ms. The initial contact was 80 logical pixels right of the measured viewport center. The visible Continuous checkbox was toggled by trusted browser input; full native Save downloads and Undo/Redo were observed.

| Browser | Continuous off | Continuous on | Release and history |
| --- | --- | --- | --- |
| Pinned SculptGL | 0 changed position components; no timer | 259 changed components, maximum absolute component change 0.1412961; timer active during hold | Timer stopped on release; one Undo exactly restored the pre-stroke SGL, Redo exactly restored the edit; Save bytes unchanged after 0/200/800 ms |
| OBrush | 0 changed position components; 0 tick permits | 292 changed components, maximum absolute component change 0.09942035; 17 tick permits observed during hold | Clock stopped on release; one Undo exactly restored the pre-stroke `.obrush`, Redo exactly restored the edit; Save bytes unchanged after 0/200/800 ms |

Both off cases left the mesh unchanged, so their first Undo reverted the preceding import rather than a nonexistent stroke. The on cases each formed one useful history step. All four browser cases passed their scoped gates with no browser exceptions or console errors. The SculptGL timer identifier and OBrush permit count are different observables and are not treated as equal dab counts. The position differences show that this is **input/lifecycle agreement, not brush-response parity**. This one Draw pose does not test the other eligible tools, moving contacts, mouse-out/tool-change/focus barriers, physical pen input, native UI, dense-scene latency, or visual similarity. All SculptGL and ZBrush parity gates remain open.
