# C153: GPU-owned pick handoff and stage boundaries

The browser's opt-in WebGPU Inflate preview previously mapped an 8-byte ray result before every dab. The new `?webgpu-preview=1&webgpu-gpu-pick=1` path lets the point candidate shader read that atomic result and ray from GPU storage directly. The same core point formula, normal refresh, failure buffer and checked sparse commit remain in use. This is a separate experimental canvas; the ordinary studio still uses WASM CPU brushes and WebGL2 presentation.

The browser waits for submitted GPU work after each dab, without mapping pick bytes. This is necessary backpressure: pointer events coalesce while a completed dab is pending, preventing an unchecked queue of deformation work. A first unpaced 10-second run applied 224 dabs, folded the surface, and was correctly rejected by the shared core. Its failed result is preserved at `.artifacts/gpu-pointer-c146/c153-fast-long-r0/result.json`. The first attempt to profile stages by awaiting a callback inside a borrowed WASM method hung and timed out; `.artifacts/gpu-pointer-c146/c153-profile-short-r0/result.json` preserves it. The final diagnostic splits synchronous submissions and awaits the working browser fence between stages.

## Geometry and history checks

The native Metal probe on an independently constructed, raw-unprotected 42-vertex/80-triangle sphere compared a readback-pick dab with a GPU-owned-pick dab at radius `0.18` and intensity `0.35`. Complete position and normal bytes matched; a background miss left positions unchanged; invalid radius rejected. `.artifacts/gpu-pointer-c146/c153-native-owned-pick-r1.json` records the result (SHA-256 `dce6c3b5897917f98502526de7733590d6904191fae5165292b3013fdaed86b0`). Its first run rejected a fixture with the wrong mask convention and is retained in the corresponding `c153-native-owned-pick.stderr`.

The normal browser imported the independently authored 999,002-vertex/1,998,000-triangle sphere (SHA-256 `dfb5316f62e392e633f03cb662dcb12215ed165a71a9ae72a3fd639528731afe`). A three-contact stroke produced the same before/after viewport SHA-256 values as the readback path: `5398141e2042c211dcd70ad09f7796b918381a54c29269fe89fc43a3ddf7903b` and `ae5446f55d34a3ac542c68812759df27ea12e933734e488ebb5265369e3b7ce7`. Visible Undo/Redo recovered those exact hashes. The GPU-owned path mapped no 8-byte pick result (readback path mapped three); both changed 5,769 vertices. The final trace is `.artifacts/gpu-pointer-c146/c153-final-short-r0/result.json` (SHA-256 `16619fe330bc6175e745d6991c1133ab7e64b30d6033ef758d24490884ddb6a8`).

The final 10-second GPU-owned trace delivered 112 dabs and coalesced 111 contacts; 25,474 vertices changed, visible Undo/Redo was exact, requestAnimationFrame P95 was `50.1 ms`, total GPU completion wait `10,254.9 ms`, and release `547.0 ms` (including `453.7 ms` for the checked commit). This **fails** the existing P95 ≤`33.34 ms` and release ≤`100 ms` gates. It did not deliver the same exact contacts as historical readback runs, so no end-to-end speed ratio is asserted. `.artifacts/gpu-pointer-c146/c153-final-long-r0/result.json` has SHA-256 `7989bea67ac0badb7ebfbade92ea5de672ebb7b83410aae8a7c531f13e3fd378`.

## Where the time went

The final three-dab browser diagnostic waited after pick, after point/normal work, and after draw. Across those three dabs, the measured browser wall times were `97.4 ms` picking, `9.5 ms` point/normal work, and `103.7 ms` drawing/presentation. These are fenced stage times, including queue and browser overhead, not isolated shader kernel timings or a sustained estimate. The same before/after/Undo/Redo viewport hashes passed; `.artifacts/gpu-pointer-c146/c153-final-profile-short-r0/result.json` has SHA-256 `6e932fc7b3610b63ff0fe9018b9e675e2b5eae559d3cc8d86df242fe63c2d47f`.

A trial 256-face GPU AABB broadphase left the short-stroke viewport exact but did not improve the sustained responsiveness gates. The unblocked/block trial delivered 108/113 dabs, with `50.1 ms` P95 in both and `562.9/545.4 ms` release; different delivered contacts prohibit a controlled speed ratio. The broadphase code was removed. Its browser result remains at `.artifacts/gpu-pointer-c146/c154-block-fast-long-r0/result.json`.

The final browser artifacts use `obrush_app_bg.wasm` SHA-256 `e90e387ea20279bf8d203c3decf79fb79cfb30ad682d03033bb6e8d081136e48`, `resident_bg.wasm` SHA-256 `3b3459664c13de44981da1206336e36bae872855a3db0f725063108c4bd61ec2`, and `web/resident-pointer.js` SHA-256 `ba872e648e1825ed3446e80a6d12a150848daf515ab147db731545d07669eaf9`.
