# C253: imported Source mirror guide and paired normalized offset

This scoped check pairs pinned SculptGL `8e45dafc0f7906e5238dfffc1a2df742bd25f29d` with the OBrush browser on the independently authored 540-byte `independent-affine-two-mesh.sgl` fixture (SHA-256 `99e107226fd5bdfeb687a4d92a61eebcec1abb2e910184e35aa58808ace105fd`). It contains an asymmetric three-vertex triangle translated +0.5 in local Z and a separate reflected/sheared quad. Both browsers import the same bytes and select the triangle. Pinned source bundle SHA-256 is `79b24bf6e1818cbb468c53cfe49783de419fd3e58f72b220aeb9308932e47600`; hosted wrapper SHA-256 is `a87cc1246a6bc39cebf81b78dcf6d6c5c6201ef72710dab7f177d1fe4acd11f0`.

The initial OBrush browser run exposed `Cannot prepare Source mirror guide: MaskConvention` immediately after SGL import, while the reference drew its active-object guide. OBrush was trying to seed the full Source geometry state through the brush's unprotected-mask admission check, although the view-only guide needs only the retained octree's loose root. A second run explicitly used OBrush's mask-conversion preview and conversion, then selected Source mode and moved its visible normalized-offset slider to `0.52`. The stored active-object offset and Undo depth changed, but the GPU guide origin stayed at its zero-offset value. The UI had not advanced the document render-snapshot revision after the metadata edit. Both failed diagnostic receipts are retained locally: `cbeb2b4c-bb25-44be-81a8-2fc621035d4a/result.json` (SHA-256 `2590ed1774fc6e947b9eaacf1da1eb340ed28041c5bf6f03324a4378141e2003`) and `73f24dd8-e3fb-4030-9db3-0e826e06c4ea/result.json` (SHA-256 `1d139d64edabf937962b6212255e5129c9edcce0afb1239069a0aaf5d6fc1fdf`). Both are under `.artifacts/sculptgl-symmetry-offset-c253/` in this worktree.

The bounded correction adds `SourceGeometryNormalState::seed_for_guide`: it validates the complete mesh and computes the same Source normal/octree producer without changing its masks, while the ordinary brush's `seed` remains strict. The Source-offset UI now calls the app's existing `changed()` publication path when the active object's offset really changes. A core regression test confirms the guide's loose root is identical for unprotected and protected versions of the same mesh, the strict brush still rejects the protected version, and the mesh's convention remains untouched.

The corrected normal-browser run passed using OBrush baseline WASM SHA-256 `a22eec5978afde522389e9d0600e2e38b6eae95224f6325a6512592da25a2cfc`. The browser build's base commit was `a4b64005f8d24eaa9fe08dbe8558dfbcfb458383`; the WASM also includes the uncommitted C253 corrections described here. The pinned triangle's local loose bound was `[1,-2,-1,4,2,1]`. Its center was `(2.5,0,0)` and at Source offset `0.5`, `getSymmetryOrigin()` moved X from `2.5` to `3.8462913036346436`, giving radius `2.692582607269287`. At OBrush UI offset `0.52`, the active guide's captured eye-space GPU origin moved X by `1.4001429080963135`, giving radius `2.6925825155698333`; the absolute radius difference is `9.169945380804734e-8`. The source and OBrush cameras differ, so this check uses the active local-X direction and compares radius after dividing by each recorded offset; it does not claim pixel equivalence. The reference's fixed local mirror ray at X `5.192582607269287`, Y `-2/3`, Z `10→-10` hit face 0 at `(2.5,-2/3,0)` with offset `0.5` and missed with offset zero. OBrush guide and reference draws had zero WebGL errors.
