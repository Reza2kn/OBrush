# C172: normal-browser Brush pair on the same 10K-vertex sphere

This advances [the C171 direct-method comparison](SCULPTGL_BRUSH_MOVING_ALPHA_C171.md) to normal UI file inputs, rendered settings and trusted browser mouse/pointer events. The independently authored, ID-colored, UV-free 10,114-vertex/20,224-triangle SGL sphere is SHA-256 `39ddfd1559fde94aa5f6d2602beffc6cf9f77fb7f934989ee9f8677739f47c1b`. The pinned SculptGL bundle is SHA-256 `79b24bf6e1818cbb468c53cfe49783de419fd3e58f72b220aeb9308932e47600`; the normal OBrush browser WASM is SHA-256 `772cd008f5bc33d89c8ad4c7a3c09fa3ab8a6f5c72d1254adf80aaa9ffde837a`. Both browsers imported the **same bytes** with source auto-centering disabled. Their mapped original Float32 positions and oriented faces match exactly for all 10,114 IDs, before sculpting.

Both normal UIs selected ordinary Brush, 25% intensity, Clay off, Accumulate off, no alpha and no symmetry; OBrush's Source mode also had fold prevention off. Source radius was 64 CSS pixels. The initial direct three-point drag requested press at viewport-center+80 pixels, two 12-pixel horizontal moves, then release with a browser frame acknowledgment after each movement. Before calibration, the two canvas/projection layouts were different: SculptGL's canvas was 1024×808 with horizontal projection coefficient `0.536931574344635`; OBrush's sculpt viewport was 1024×768 with coefficient `0.5147326588630676`. Giving both an unadjusted 64-pixel radius and 80/92/104-pixel offsets therefore requested different world rays/radii. The unadjusted saves changed 96 versus 109 vertices, with 109 differing mapped output vertices and maximum component difference `0.0019033551216125488`. A one-move unadjusted run changed 87 versus 98 vertices and differed at 98 vertices by up to `0.000964045524597168`.

The calibrated OBrush run used the ratio `0.5147326588630676 / 0.536931574344635 = 0.9586559693222311` for both horizontal offsets and radius. Its normal UI radius was `61.35398203662279` pixels; the public UI state reported that same value. The initial horizontal world-ray offsets then differed by at most `1.6653345369377348e-16` and world radii by `2.7755575615628914e-17` under the actual orthographic projection matrices. This matches the requested initial rays/radius, **not** every later picked surface contact by assumption.

With one calibrated move, both public saves changed the same 87 vertex IDs; 10 mapped vertices (11 components) differed, with maximum/RMS component differences `2.9802322387695312e-8` / `2.419597138882212e-10`. With two calibrated moves, both changed the same 96 IDs; 19 mapped vertices (21 components) differed, with maximum/RMS differences `5.960464477539063e-8` / `8.387194415631603e-10`. Every oriented face stayed in place. A fresh repeat of the two-move pair produced exactly the same per-side public After-file SHA-256 values (`b2688eced5bf2d445bd925aed1778557de57989aeb618249f76c03596079d54b` in SculptGL; `2bc0a15e52c105e5a327e4ea9440b9ddd3b9f15ccfc3115dd75e3e93591e3855` in OBrush) and the same 96/19/21 numerical counts. Both apps' public Undo and Redo files exactly recover their own Before and After bytes in these useful runs. The source and OBrush formats differ, so cross-app byte identity is not claimed.

The final run adds a read-only DOM capture-phase observer. Each page received three trusted `pointermove`/`mousemove` pairs, one trusted down pair and one trusted up pair on the normal page. OBrush reported two applied dabs; the source runtime did not expose an equivalent public dab counter in this run. The final source receipt is `.artifacts/sculptgl-ui-brush-pair/source-0c772591-d06a-4742-8037-32d7fcfb0ccc/result.json` (SHA-256 `08d93e20e2b193a820fb7d9b3241d975e3267599d8a8dbcd94c29e0a700e4d5c`); the OBrush receipt is `.artifacts/sculptgl-ui-brush-pair/root-1ea3b838-a9ce-4a60-a925-9a550ca1a988/result.json` (SHA-256 `8100c2b6a42bbbc1d6da031d4d4b07083366158c529e6ce363df4add73d3d6cd`); the independent whole-save mapping audit is `.artifacts/sculptgl-ui-brush-pair/source-0c772591-d06a-4742-8037-32d7fcfb0ccc/paired-audit-root-1ea3b838-a9ce-4a60-a925-9a550ca1a988.json` (SHA-256 `5dbe2d10af63c89feb0f0088c1ce39cbffb10dd2621752619d28b6910c8a34f3`). The audit maps IDs from original vertex colors and compares all 10,114 Float32 position triples, all oriented faces and mapped color/material/mask attributes in both public saves. All mapped attributes are identical before and after, and stable across each stroke.

The harness failures are retained. Three attempts to enable the reference Accumulate checkbox after setup failed to publish the setting, so this normal-UI pair explicitly uses Accumulate off on both sides; it does not retroactively test C170's accumulated mode through the UI. A press without movement produced no geometry in either app and failed the audit's useful-change/history gate. An initial attempt to bind a three-point run against an older source receipt failed its stroke-mode identity check. These are setup/diagnostic failures, not hidden passing strokes.

This is a strong numerical and usability comparison for one normal orthographic Brush drag on one static sphere. It does not establish exact per-dab source invocation counts, arbitrary camera/viewport framing, alpha/pressure/symmetry, other tools, dense-mesh quality, native GUI behavior, the failed million-vertex responsiveness gate, or full SculptGL/ZBrush parity. The preexisting 60-second comparison remains the relevant performance evidence.
