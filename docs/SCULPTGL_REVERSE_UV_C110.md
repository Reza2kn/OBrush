# C110: UV-preserving Reverse levels

OBrush now retains a fine level's original UV coordinate IDs and face-corner assignments when Reverse renumbers its geometry. A versioned `sculptgl_static_smooth_v4` hierarchy permits a saved child to split canonical UV aliases while requiring every face-corner value to match its parent's static prediction; one saved ID cannot merge two distinct predicted chart IDs. That validation runs again on project import. A UV value edit inconsistent with the recoverable subdivision still rejects before replacing the document and leaves redo available.

Repeated Reverse reorders finer UV face rows through the same physical vertex and oriented-face correspondence used for geometry. Each finer level keeps its own coordinate table, including aliases. A candidate is validated and budgeted before committing one history transaction. Existing `v1`–`v3` project interpretation remains unchanged.

The [paired C110 receipt](evidence/sculptgl-reverse-uv-c110.json) uses the same independently authored 25-vertex, 16-quad nonplanar UV-grid OBJ in OBrush and the pinned SculptGL browser (fixture SHA-256 `f51f9af14a1e09d681e1dc1dc366ef2854eed48c74206ca65b7330f49a3e0361`). Both normal UI paths recover 25/16/25 → 9/4/9 → 4/1/4 vertices/faces/UV coordinates. At import and both recovered levels, mapped physical positions and every oriented face-corner UV value match exactly. After returning to the finest level, oriented face-corner UV values still match; the largest mapped position difference is `7.450580596923828e-9` world units. Each app retains its own imported 25-entry UV table at the finest level. The apps' intermediate UV ID ordering differs, so the paired comparison is about physical corners and values, not equal numeric IDs across applications.

The normal OBrush browser path passes two Reverse clicks, exact original finest-level UV IDs/corners, lower/higher navigation, second-command undo/redo, save/reload and complete GPU/save agreement. The shared-core tests cover an independent UV alias patch, exact fine coordinate IDs after save/history, rejection of a tampered saved UV value, an inconsistent midpoint rejection that preserves redo, and repeated Reverse on the UV grid. The first browser run failed only its oracle because it sorted UV rows separately within each face; the [failed receipt](../.artifacts/sculptgl-paint-static-runtime/reverse-c110-13f28f26-40bf-4ca9-a200-9e1970665d11/result.json) is retained. The corrected run compares all physical corners independent of face order.
