# Sparse held-pointer Source Worker trial (unpromoted)

The experimental `?source-worker-held` route now transports checked changed rows for each preview and patches the active WebGL vertex buffer with at most 16 bounded subdata calls per flush. A complete scene and mesh check remains at release before one public history commit. The trial button is off by default. This is a correctness diagnostic on one 40,962-vertex sphere, **not** an ordinary brush responsiveness or SculptGL/ZBrush parity result.

## Browser observations

Two held strokes were drawn through the ordinary viewport pointer route: `(750,450)→(775,460)` then `(820,450)→(845,460)`. Each acknowledged three Worker dabs. The first cold stroke's pointerdown-to-first-preview was 149.2 ms, with a 121.9 ms begin reply; the second warm stroke's values were 355.9/343.5 ms. The maximum main-thread preview callback was 0.4 ms and maximum Worker apply call was 26.4 ms. Release-to-public-commit was 241.1/223.7 ms. These are two samples, not a frame-time distribution.

The Worker emitted three sparse packets per stroke. During live preview, all six position/normal words matched active VBO readback for the 172 touched rows in stroke one and 164 in stroke two. After each public Save, all 122,886 active VBO position words matched the saved mesh. Retained display normals can intentionally differ from saved mesh normals, so the saved normal array is not a valid GPU normal oracle. Instrumentation observed 86 subdata calls and 88,520 uploaded bytes across the two strokes plus one cancelled preview; this is an aggregate, while the renderer enforces a maximum of 16 calls per flush. No browser exceptions or GL errors were observed.

The normal **Save project** shortcut after stroke one produced SHA-256 `b7c817530a9db49702d6180f63b205e910e4b27f34facb0aa170c3d2452e2e1e`; after stroke two it produced `d5d3dcca4483c9a46c038beeec661f2c857f0810e3a92e9af5d06513b947bbda`. Normal Undo then Save was byte-identical to stroke one; Redo then Save was byte-identical to stroke two. Losing primary pointer contact during a third preview cancelled the gesture: full VBO SHA-256 and public Save stayed identical to the pre-cancel state. A 500 ms post-release observation found no additional sent dabs after either committed stroke.

Each committed stroke discarded one queued endpoint sample at release (`lastEndpointDropped=true`), so this route can stop short of the actual mouse-up position. The preview owner check is deliberately provisional: document revision, mesh identity and retained-state identity avoid per-dab full serialization, but the final complete-scene digest is authoritative. A core test demonstrates that an in-place mutation can pass the provisional witness and is rejected at final publication. Other UI document publications cancel the held preview; control/style/view changes reject the final commit. A zero-effect Worker release preserves redo in a core test, but the no-op browser UI path was not exercised here.

Core geometry still allocates full-vertex normal scratch and copies full domain-normal words per changed dab. The released result also encodes and checks complete geometry. The frozen 100k/million-vertex sustained-pointer gate, endpoint fidelity, 1m worker CPU cost, and broad mutation matrix remain open. Keep the trial query-gated and off by default.
