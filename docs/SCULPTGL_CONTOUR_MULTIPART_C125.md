# C125: selected contour over two transparent objects

The later [C126 matched-camera run](SCULPTGL_SGL_OPEN_CAMERA_C126.md) found and fixed a legacy SGL Open camera path. Its paired contour footprints are nearly equal; the 29.2% value below describes the earlier unmatched-camera state and is retained as diagnostic history.

The pinned SculptGL revision `8e45dafc0f7906e5238dfffc1a2df742bd25f29d` and frozen C124 OBrush web build (`b646dba6cd369658f45610e53c8c4db27a53fc31478fdca457bfea931a19bfb2`) imported the same independently authored `transparent-overlap.sgl` (SHA-256 `7e84bc57eae25e30f8b95af37d580cd2d9ffc48c6d96b26db0d73b28ecdbbab6`). It contains two offset, overlapping quad sheets, each at 50% opacity. Both consumers report two meshes/parts and select the second, front purple sheet. The source run switches contour through its application controller; OBrush uses the visible checkbox. The source runner clears its starter scene through its API, whereas OBrush's file input replaces the document, so the setup routes differ.

Each host's off/on screenshot subtraction is confined to the selected purple sheet's silhouette; the exposed green rear sheet contributes no contour edge. In the viewport crops, SculptGL changes 3,993 RGB pixels in a 495×496 bounding box; OBrush changes 3,867 in a 352×391 box. Dividing by the respective bounding-box rectangle perimeters gives **2.0146 vs 2.6023 changed pixels per perimeter pixel**, an OBrush excess of about **29.2%** for this fixture. A horizontal cut through the left/right edges at screenshot y=430 has two changed pixels per SculptGL edge and three per OBrush edge. These are screenshot-space diagnostics with different cameras, viewport sizes, materials and AA; the width excess is an observed mismatch, not a tolerance pass or a complete occlusion assessment. The unselected sheet is visible behind the selected sheet, but the fixture does not test a selected object hidden by an opaque foreground object.

A second pinned-source run set its canvas to exactly **1140×826**, matching OBrush's measured viewport pixel dimensions at DPR=1. Its selected contour still changed 3,821 pixels over a 474×474 bounding box, or **2.0153 pixels per rectangle-perimeter pixel**. This rules out canvas dimensions alone as the explanation for the 2.6023 OBrush footprint; the object is still framed differently (474×474 vs 352×391), so camera/pose/material/AA alignment remains required before calling the line-width difference intrinsic to the shader. The matched-canvas source record is `.artifacts/contour-multipart-c125/source-matched-1792281761166/result.json`.

OBRush's off/on/off checkbox sequence preserves the complete saved project SHA-256 `bf3128aab946e333c4b55da3378b5f631e6691186775ca60e00e7647b5df3895` (3,709 bytes). Both browser runs finish with zero reported exceptions or console errors and close owned browsers/servers. Raw records and screenshots are in `.artifacts/contour-multipart-c125/source-1792281441884/` and `.artifacts/contour-multipart-c125/root-1792281450532/`; [machine-readable evidence](evidence/sculptgl-contour-multipart-c125.json) carries hashes and measurement details.

A separate DPR=2 CDP override initially failed to reach the checkbox. The owned browser harness explicitly launched Chrome with `--force-device-scale-factor=1`, so the override conflicted with its process setting: the screenshot was 3200×1826 but the canvas backing buffer stayed 1600×913 and the right panel moved outside the captured layout. That failed run remains under `.artifacts/contour-multipart-c125/root-dpr2-1792281518193/` and `root-dpr2-metrics-1792281558767/`. A first run with a true process-level DPR=2 also missed the checkbox because it reused the DPR=1 fixed click coordinate; that failure remains under `root-real-dpr2-1792281670275/`.

After launching owned Chrome at DPR=2 and correcting the click to the visible control, OBrush passed the same imported two-part contour off/on/off and exact project-preservation check with zero browser errors. Its CSS viewport was 1600×913 and canvas backing was correctly 3200×1826. The pinned source also passed off/on at process-level DPR=2, but its reported canvas backing stayed 1290×873 while its screenshot was 3200×1826. On these unmatched backing resolutions, screenshot-space normalized contour footprints were 5.9992 for SculptGL and 2.5027 for OBrush; they are **not** a direct thickness-parity comparison. The successful high-DPI browser records are `root-real-dpr2-corrected-1792281692913/` and `source-real-dpr2-1792281706062/`. Physical high-DPI hardware, controlled matched render resolution/camera/AA and opaque occlusion remain open.
