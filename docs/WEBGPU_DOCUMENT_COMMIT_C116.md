# C116: checked resident-GPU result handoff to a document

The shared Rust core now has a transaction boundary for a GPU position result: `ResidentDocumentInput::commit_position_bytes` accepts a complete little-endian 16-byte-per-vertex position buffer only for the source mesh and active subtool from which that resident input was captured. It streams the complete editable `Mesh` through SHA-256 at capture and at acceptance, so it does not retain a second source snapshot or allocate a serialized mesh string. It also compares the saved local-to-world pose bitwise, verifies the active subtool and visibility, and rejects an open stroke, retained subdivision hierarchy, layers, morph target or redo branch before a useful commit. An exact no-op retains redo.

Every row must contain finite bounded XYZ and an exact `w=1`; the byte count must match the captured vertex count. Fully protected vertices must remain bitwise unchanged. The candidate is a fallibly allocated copy of the active mesh, so RGB, mask, material and UV channels are retained. The existing shared-core surface fold guard must accept the entire proposed deformation at scale `1.0`; a clipped or rejected result does not alter the document. Only then does ordinary `Document::replace_mesh` validate and commit a single undo snapshot. Invalid or stale input never replaces the document.

The native Metal end-to-end probe uses an independently constructed `Mesh::sphere(2)` with 162 vertices and 320 triangles, one point pass at local center `[0,0,1]`, radius `0.5`, intensity `0.1`, and all default unmasked vertices. The actual GPU readback changed seven vertices. All three position components matched the shared scalar point reference exactly (`max absolute component difference = 0`). The result entered `Document` through the new boundary; Undo restored the exact prior versioned JSON and Redo restored the exact accepted JSON. A nonfinite readback was rejected without mutation. This verifies a real native GPU readback-to-history path, not a SculptGL Inflate brush comparison.

Unit cases additionally check stale mesh channels, a changed active subtool, stale affine pose, fully protected vertices, invalid byte count/fourth word/nonfinite coordinates, an open stroke, retained levels, an unsafe fold, a no-op with redo and a useful result that would replace a redo branch. The GPU output is deliberately read back in full for this diagnostic. Production sculpting needs a resident document/brush/history design that avoids that transfer, handles all brush semantics and preserves the normal browser CPU fallback. The normal OBrush browser still uses WASM CPU geometry and WebGL2; this report makes no SculptGL/ZBrush feature or sustained-performance parity claim.

Formatting, all 2,453 workspace tests, strict native workspace and core/GPU WASM Clippy, and the official browser build passed. A scoped normal-browser scene/formats run passed ten cases with 71 actual downloads and 66 GPU/save checks; its owned Chrome exited zero and server closed. That browser run checks that the changed core dependency does not regress these existing workflows; it does **not** invoke the new GPU commit path. An initial harness command failed because its required frozen-web directory was omitted. The failure is visible in the task transcript, but the corrected run reused the local log path, so there is no separately hashed failure receipt. The acceptance key binds the active mesh, pose and subtool, not every inactive scene field; a separate document with byte-identical active state could satisfy the key if a caller explicitly passed it.
