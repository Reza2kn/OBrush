# MRP01: contiguous attribute witness trial for million-vertex Source upload

This preregistration starts at `0bdd54754fde1d326e0440ba717d94c71b1c04ab`, before changing the renderer. The ordinary C264 browser baseline uses the 999,002-vertex fixture SHA-256 `dfb5316f62e392e633f03cb662dcb12215ed165a71a9ae72a3fd639528731afe` and frozen 60-second protocol SHA-256 `234870ed03a240931a22f421968917efaeed8becc1df834c998bbe3e9c101a33`. It recorded 957 dabs, 66.7 ms active RAF P95, 68.0 ms app RAF CPU P95, 159.0 ms release acknowledgment, and 0/4 responsiveness gates. Mean Source geometry was 22.943 ms (6.843 retained match, 7.116 state advance); mean renderer callback was 15.879 ms (4.260 scene admission, 10.328 upload). Nested samples are not additive or a causal profile. In the retained C264 scalar recorder, 956 geometry VBO `bufferSubData` calls transferred 3,446.8 MB but their observed JS call time totaled 82.0 ms (0.086 ms per call); GPU completion is outside that timing. This makes CPU-side renderer work a plausible target but does not isolate the scan from packing and cache updates.

The current selected-chunk upload scans all million *interleaved* 40-byte cached rows on every selected Source dab, even when mesh masks, colors, and material words are unchanged. The trial retains bounded exact color words alongside the existing packed GPU-row, raw-mask and material witnesses. It first compares each canonical channel contiguously and bitwise. Only channels whose complete witness differs need a per-row changed-chunk scan. Geometry still uses the selected normal-state chunk witness and exact changed-row check. An absent or stale witness falls back to the existing full scan/upload; no hash, pointer identity, epsilon, or probabilistic shortcut is allowed. The additional color witness is charged within an explicit per-object CPU cache cap. Native and browser use the same renderer source; the shared Rust geometry and public project/history formats do not change.

Before browser admission, focused tests must check that one changed color, raw mask (including distinct raw values with the same display f32), material, position, and selected normal produces the same uploaded row ranges/buffers as the old algorithm; signed zero and NaN words must remain bitwise. Check bounded allocation and fallback, `cargo fmt`, workspace tests, strict native/WASM Clippy, and `scripts/build-web.sh`. A diagnostic microbenchmark measures only the attribute-comparison substage on independently authored 999,002-row arrays with unchanged channels; changed-channel behavior is checked by separate exact oracles. Run its old interleaved and new contiguous cases for 25 rounds in the same process; require exact zero-change counts and contiguous elapsed time below half the interleaved elapsed time. It is not a full-mesh, browser, or responsiveness measurement.

If those pass, run the same frozen 1m/60s protocol in fresh owned Chrome, save Before/After/Stable/Undo/Redo and independently audit exact file/history/shape checks. Capture actual GL row words against the retained Source display-normal oracle, app/console/GL errors and clean browser closure. Record selected scan/upload/scene admission/geometry timing, VBO bytes/calls, RAF interval P95/max, app CPU P95, release acknowledgment and all four responsiveness gates. The predeclared browser admission target is selected-scan mean below 2 ms, mesh-upload mean below 9 ms versus C264's observed 10.328 ms, active RAF P95 no greater than C264's 66.7 ms, and release acknowledgment below 160 ms, alongside all correctness gates. A different delivered-dab count prevents causal speedup or equal-output claims. Reject if any target fails. A substage win alone does not establish SculptGL parity.

## Completed trial and decision

**Rejected; renderer source restored to `0bdd547`.** The exact-channel witness was correct in focused tests, but the ordinary browser path got slower and missed three of the four preregistered admission targets. The ignored candidate patch and frozen browser receipt are retained under `.artifacts/mrp01/`; neither is a product change.

The 25-round 999,002-row attribute-only debug benchmark reported 4,128.770 ms for the old interleaved walk and 19.205 ms for the contiguous witness, with zero changed rows in both. This proves only the narrow unchanged-attribute substage. The focused oracle tests covered position-only, selected normal, one color, raw mask (including identical display f32 with distinct source words), material, empty colors, mask convention, signed zero, NaN words, and fallback. The first focused compilation failed because the ignored benchmark called private `Mesh::new`; the corrected public sphere fixture passed. Strict Clippy first caught test-only needless allocations and passed after correction. The first web build failed because the script expects a worktree-local `target` path even when `CARGO_TARGET_DIR` points to the shared target; a local symlink fixed this, and the symlink was removed after building. The final candidate passed `cargo fmt`, `cargo test --workspace --locked --quiet`, strict workspace Clippy, strict WASM-target Clippy, and `scripts/build-web.sh` before the browser run. These corrected failures remain part of the trial history.

The frozen 1m/60s browser run used fixture SHA-256 `dfb5316f62e392e633f03cb662dcb12215ed165a71a9ae72a3fd639528731afe`, protocol SHA-256 `234870ed03a240931a22f421968917efaeed8becc1df834c998bbe3e9c101a33`, runner SHA-256 `4d8949f0835a433afa1130b2280c3c1be52026df49b1415838fc8922d9225388`, and portable WASM SHA-256 `b6bd4413f382f1a836b736bff1ce2a22344be5c31f213ef2fb62c7b8e4ac06e2`.
