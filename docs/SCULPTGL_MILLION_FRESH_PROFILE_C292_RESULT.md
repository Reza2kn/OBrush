Different delivered dab counts and timer overhead mean this run is for attribution, not a causal speed comparison.

Across the same 1,423 `viewport()` calls, mean time was **34.88 ms**. The nested probe recorded queued dab processing **15.41 ms**, source viewport preparation **2.13 ms**, input/modal handling **0.46 ms**, continuous-frame handling <0.001 ms and render callback setup **0.006 ms** per call. The difference of about **16.87 ms per call** is uninstrumented viewport work; it must be retained as a residual, not assigned to any specific line. The existing revision-triggered render-snapshot timer recorded only three samples averaging 1.8 ms, so it cannot explain the residual. The renderer paint callback is outside this viewport scope and separately averaged 15.30 ms across its own sample population. A timer inside `process_dabs` encompasses shared-core geometry and host work and cannot be treated as a new independent cost. None of the measured narrow subphases supplies the preregistered same-state microbenchmark evidence for a correctness-preserving ≥5 ms reduction, so **no product candidate is admitted**.
