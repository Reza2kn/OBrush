# C104: bounded Rust reconstruction of the static fine ring

[C103](SCULPTGL_RING_RECONSTRUCTION_C103.md) predicted SculptGL's face visit and first fine-vertex neighbor in an independent Python diagnostic. C104 ports that reconstruction to the display/GPU-independent [shared Rust core](../crates/obrush-core/src/source_ring.rs). `SourceStaticRingMap::build` takes a validated parent and its static child, uses face-corner UV IDs for the 32-entry pseudo-vertex cache visit, derives child edge/quad-center IDs from the parent, verifies the child topology and returns the first neighbor in OBrush's physical child-vertex order. `transport_positions` applies the source's raw face-averaged normal and first-neighbor tangent frame to retained fine residuals. Both methods are pure calculations; the subsequent [C105 integration](SCULPTGL_STATIC_FRAME_C105.md) connects them to a new versioned live hierarchy.

The [reference-backed integration test](../crates/obrush-core/tests/source_static_ring.rs) imports the same three independently authored all-seamed OBJ fixtures through the studio import path. Its committed [expected values](../crates/obrush-core/tests/fixtures/source-static-ring-reference.json) were mapped from the pinned C102 SculptGL snapshots by pre-edit physical position. The test compares all 15 parent face visit IDs, all 50 first-neighbor IDs and every coordinate after the same direct coarse edit `(0.125, -0.09375, 0.0625)`. It also rejects an unrelated child and exercises a non-UV sphere plus a larger seamed sphere for coverage. Exact numerical differences, hashes and final checks are in [C105 evidence](evidence/sculptgl-static-frame-c105-0.1.20.json).

At the C104 checkpoint this was an implementation component, not a production coarse-edit or SculptGL parity claim. [C105](SCULPTGL_STATIC_FRAME_C105.md) adds a retained map and a versioned studio path. Long-stroke performance, arbitrary UV/topology reference comparisons and complete browser editing behavior remain open.

An initial test used the legacy `Mesh::from_obj` parser and failed the quad-cube face-order comparison: that parser triangulated the six original quads into twelve faces, yielding `[8,4,0,9,6,1,5,2,10,11,7,3]` instead of the reference's six-face visit `[4,2,0,5,1,3]`. The final test uses the product's `Mesh::import_obj` path, which retains original quad/UV topology. This failed check is a fixture-route error, not evidence that the completed map handles arbitrary quad imports.
