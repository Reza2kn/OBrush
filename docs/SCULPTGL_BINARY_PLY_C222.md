# C222: SculptGL-profile binary PLY export and return

The SculptGL-profile **PLY binary** File control now uses a separate shared-Rust
writer. It merges the selected or all scene parts in order, bakes editable
world poses, retains original tri/quad face records where available, writes
float32 XYZ and 8-bit RGB, and offsets face indices across parts. Its header
and zero padding follow the pinned SculptGL binary exporter. The upstream
writer reserves a face index array that counts each quad once as a quad and
twice as triangulated faces, then doubles that reservation; therefore a quad
adds 48 extra zero padding bytes beyond the already unwritten second copy of
its 17-byte face record. The ordinary OBrush PLY encodings remain separate.
The reference-identifying `comment created by SculptGL` line is retained for
format compatibility; the file is generated by OBrush.

The shared Rust PLY importer now accepts that exact bounded padding and
nonplanar quads on this SculptGL-marked path. Other PLY files still require
planar polygons and reject undeclared trailing data. The independent
nonplanar-quad fixture checks a 65-byte zero tail, RGB decode, two generated
triangles, and rejection of truncated or nonzero padding. The exporter fixture
checks an original quad plus a second-part triangle, all bytes in the header,
8-bit RGB and face offsets, exact zero tail, UV loss reporting, project
immutability and successful re-import. At C222, imported quads were
triangulated; [C223](SCULPTGL_PLY_QUAD_RETURN_C223.md) subsequently retained
valid quad metadata and checked an exact reference-file return.

The normal Chrome paired run uses the same independently authored two-object
OBJ imported into both applications. OBrush exports those two selected objects
through its visible File control; pinned SculptGL exports its scene including
its startup sphere through the unmodified `GuiFiles.saveFileAsPLY()` runtime
method. The imported-object tail has six vertices and two faces in both files.
All RGB bytes and relative face records match, and the maximum measured world
position-component difference is **0** for this fixture. OBrush's selected
file has the expected 26 zero padding bytes. SculptGL's 98,312-vertex,
98,306-face file has 6,389,786 zero padding bytes; the reference download is
