# C114: saved-document WebGPU render and world-ray probe

The isolated `obrush-gpu` probe now accepts a versioned `.obrush` project through the ordinary `obrush-core` decoder. It captures only the visible active subtool, leaving the decoded project and its history outside GPU ownership. The browser API loads that bounded snapshot into a WebGPU canvas, composes the saved local-to-world pose with the supplied world camera in f64, and converts unit world-space pick rays to local rays in shared Rust before the GPU's bounded f32 picker. Native Metal and browser WebGPU use the same core snapshot, point buffers, pose and ray conversion.

The checked fixture is a 2,446-byte v7 `.obrush` save from OBrush's earlier import of the included **independently authored** five-point, three-triangle SGL scene. The source SGL SHA-256 is `dbf724eacab383f647ec8f36655424d53cb14cf60e74d258ea10a169f8ee5c69`; the saved project SHA-256 is `cd59216de8039d6d73026e92851923a317530ff6bd92f7b6b6ea5494cd22a2d5`. It retains one quad plus one triangle, distinct UV corners, RGB/material/mask channels, reflection and shear, and a large world translation: `[262144, -131072, 4096]`. The 16 local-to-world words in the fixture are preserved, not flattened into f32 world vertices.

The probe uses the production `SourceCameraFrame` math with a 512×512 orthographic frame centered on transformed world bounds `[262142.125,-131072.75,4096]` to `[262147,-131071.25,4096]`, identity view rotation, zero plane offset, 45° FOV parameter and zoom `2.8 × 4.875 = 13.65`. It checks a 6×6 pixel-center grid at x/y `96, 160, 224, 288, 352, 416`; seven rays hit. All seven native GPU face IDs equal `Document::raycast_scene` with world-distance selection. Browser WebGPU matches native Metal on all seven local face, distance and position values, both when given the prepared local rays and when given the original world rays. The maximum browser world-position component difference from the CPU picker is `4.889443516731262e-8`. The entire 512×512 browser WebGPU canvas and an explicitly drawn offscreen GPU image match the native Metal RGBA image in **every channel**. An invalid project and invalid camera matrix are rejected. The native saved document JSON remains unchanged.

The owned browser run reports no device errors, JavaScript exceptions, console errors or blocked external requests, and closes Chrome with exit code zero. Its GPU trace shows two 9-index draws, fourteen 8-byte pick maps, no position readback, and one later 1 MiB diagnostic image map after the explicit offscreen draw. These are API observations for a tiny scene, **not a responsiveness measurement**. An earlier PNG comparison failed because the test requested offscreen pixels after only drawing the canvas; the offscreen target had not been drawn. The corrected test explicitly calls `draw()` before the offscreen readback. A repeat attempt also hit the harness's existing isolated-profile directory and was rerun with a new owned output directory. Both failures are preserved in local audit output.

After the final changes, formatting, all 2,447 workspace tests, strict native workspace Clippy, strict core/GPU WASM Clippy, the GPU WASM release build and the official `scripts/build-web.sh` passed. The normal OBrush browser's scoped scene/formats host run passed ten cases with 71 actual downloads and 66 visible GPU/save checks, then closed its owned Chrome/server. That normal route still uses its existing WASM CPU sculpting and WebGL2 viewport; the scoped run is a regression check, not proof that the GPU probe is installed in the studio.

This is still a separate diagnostic canvas, not the normal OBrush studio renderer. It covers one visible active subtool; the current shader displays vertex RGB but ignores saved UV/material/render settings, lights with local normals, and does not yet transform normals for reflected/sheared objects. It does not implement multi-subtool composition, live Source brush semantics, document/history GPU transactions, CPU fallback, device recovery, or the failed million-vertex 60/120-second browser responsiveness gates. No SculptGL or ZBrush reference parity follows from this probe.

The [C114 evidence](evidence/sculptgl-webgpu-document-c114.json) records fixture/build/result hashes, exact parameters, numerical differences, actual GPU API observations and validation results.
