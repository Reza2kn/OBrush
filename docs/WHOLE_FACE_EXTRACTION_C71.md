# Whole-incident-face extraction option (C71)

OBRush now offers a **Whole incident faces** checkbox in the mask-extraction inspector. The default remains the existing interpolated clipped boundary. The new option admits a complete source face when any of its indexed vertices reaches the mask threshold. It shares the Rust core, input limits, source validation, shell construction, checked SubTool append, and Undo/Redo path with clipped extraction. The option is session state, not a project-schema field.

At threshold 0.5, an independently authored unit square has four vertices, two triangles, and mask values `[0,1,1,0]`. Both source triangles touch a qualified vertex. Default clipping gives five patch points and three triangles. Whole-face selection gives the four original points and both original triangles. At zero thickness, that is an open 4/2 patch. At −0.125, it is a closed 8/12 shell with signed volume 0.12499999999999999; absolute error from 0.125 is about 1.4e−17. The saved source and mask remain exact; the new part is independent and unmasked. The core fixture also checks +0.125, edge orientation and exact whole-document Undo/Redo.

Validation: `cargo fmt --all`, full `cargo test --workspace --all-targets`, strict native workspace Clippy, strict WASM core Clippy, official `scripts/build-web.sh` and `scripts/package-macos.sh` passed. The owned Chrome normal-UI run passed all ten mask-filter/extraction workflows. It exercised the visible checkbox, both thickness values, saved public `.obrush` files, visible GPU buffers, and exact Undo/Redo. Its 115 saved snapshots, no GL/JS runtime errors, actual 4× MSAA, 8,835 visible-control boundary checks with zero failures, and clean Chrome/server shutdown are recorded in the [browser result](../.artifacts/mask-filter-browser/whole-face-c71-1b0e1e48-9367-40c9-9fc4-0f915d54ecdf/result.json).
