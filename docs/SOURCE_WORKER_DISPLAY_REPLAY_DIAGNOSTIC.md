## Required future trace, frozen before capture

The script accepts `source-display-replay-trace-v1.json` beside a retained `result.json` or via `--trace`. The trace schema is `obrush-source-display-replay-v1`, with exact `result_sha256`, `before_sha256`, copied `product_binding`, `accepted_dabs`, and ordered `events`. Each `dab` must bind its consecutive accepted sequence and actual Worker reply `worker_message_id`, record sorted unique **selected** vertex IDs (including selected vertices whose positions did not change), and sorted unique `[id,x,y,z]` post-dab position rows. The renderer's preview packet is insufficient by itself: it carries changed rows, not necessarily the complete selected set. An `after` and `stable` checkpoint follow all dabs. Undo and Redo each require an explicit `history` event with the selected history union and restored position rows, followed by its checkpoint. A complete trace must be read-only, independently bounded and captured from the accepted producer/history boundary, not inferred from final Save or 24,000 requested pointer moves. Store its own SHA-256, byte length, source/build hashes, and failure/overflow state. A missing, truncated, unbound, unsorted or extra event is a failure, never an empty selection.

The offline output compares replayed positions against each complete public project and replayed display-normal f32 words against exactly one error-free active VBO at Before/After/Stable/Undo/Redo. It also checks the GPU position words against public positions. It emits `replay_completed` only when all five states match; `replay_mismatch`, `missing_replay_evidence`, or `invalid_replay_evidence` exit nonzero. Analytic self-check covers two triangles, stale unselected normals, selected refresh, restoration and duplicate-ID rejection. This is a diagnostic of producer-to-VBO behavior, not a SculptGL reference comparison or a performance admission.
