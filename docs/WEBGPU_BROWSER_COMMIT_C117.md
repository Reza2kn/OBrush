# C117: browser WebGPU positions into shared WASM document history

The isolated browser GPU crate now exposes `ResidentDocumentSession`. It decodes an ordinary versioned `.obrush` project through `obrush-core`, captures the same checked `ResidentDocumentInput` as the native path, and accepts a WebGPU position readback through the C116 commit boundary. This document authority is separate from `ResidentProbe`'s canvas; Undo/Redo changes the document, and the probe does not automatically synchronize its displayed mesh to that history state. The normal OBrush studio does not call either diagnostic object.

The comparison uses `resident-sphere-162.obrush`, an independently generated 17,845-byte v2 save of `Document::new(Mesh::sphere(2))` (SHA-256 `ab16459719d55e25d49fa8c2cc0fd16809749a991a6d08e960f6a822d34afe0a`). It has 162 vertices and 320 triangles. Native Metal and browser WebGPU each ran one point-program pass at local center `[0,0,1]`, radius `0.5`, intensity `f32(0.1)` (`0.10000000149011612`), with no added masks or symmetry. Seven vertices changed. Native GPU XYZ agreed exactly with the shared scalar reference on this fixture.

The complete 2,592-byte browser WebGPU position buffer and native Metal buffer have identical SHA-256 `602ae3297642001c1249fb6d953b8c7b4bcf87eb69897410d8df826ac2d20337`. Each host passed those actual bytes to its own Rust document instance. Their complete accepted `.obrush` JSON bytes match exactly (SHA-256 `78ee164193035562df3690cd6c399dd9a1f8fa8c1aefc132eb986a86d4cc47c5`). Browser input rejection of a nonfinite word preserved the original project; the useful result committed; a second stale commit rejected; Undo restored the original project string exactly and Redo restored the accepted string exactly. The browser used a distinct project decoder instance from its GPU canvas, so the match checks the shared Rust handoff rather than a JavaScript patch to the document.

Both explicit offscreen GPU draws and actual 512×512 browser canvas screenshots changed **20,146 pixels** with a front-facing camera. The offscreen pair changes 27,357 color channels, with a largest absolute channel difference of 113. The browser trace records six compute dispatches, four 960-index draws, one 2,592-byte position map, one 4-byte failure-word map and two later 1 MiB image diagnostic maps. It records no GPU device errors, JavaScript exceptions, console errors or blocked external requests; the owned browser exited zero and its server closed.

Two earlier runs remain as failures. The first compared immediate canvas screenshots with the identity clip matrix and saw no difference. A second added synchronized offscreen draws; they too were identical, disproving a mere presentation-delay explanation. That matrix made the edited +Z side the farther, hidden surface. The final run flips clip Z to face the edited side; both synchronized offscreen and canvas images then change. The failed result JSON/screenshots and final result are kept in separate local output directories; no tolerance or pixel threshold was relaxed.

Formatting, all 2,453 workspace tests, strict native workspace Clippy, strict core/GPU WASM Clippy, the GPU WASM release build and lockfile-matched bindgen conversion passed. The three GPU `.obrush` fixtures have explicit `.gitignore` exceptions so the source and comparison cases can be carried with the project.

The point program is not a production Source or SculptGL Inflate brush, and this fixture is too small for a responsiveness claim. The full GPU position readback is intentional diagnostic transport and would be costly for large meshes. There is no live studio input, multi-subtool composition, continuous stroke history, GPU/CPU fallback or recovered device state here. Native/browser exactness against the same algorithm does not establish independent SculptGL or ZBrush response, quality or performance parity. [C117 evidence](evidence/sculptgl-webgpu-browser-commit-c117.json) binds source/build/runtime hashes, numerical outcomes, failed checks and these limitations.
