# C166: pinned runtime JPEG alpha bytes and mirrored sample pair

The same independently encoded 16×16 grayscale JPEG used in C164–C165 (SHA-256 `0edf90c34f0d33c65d63fc6a9a70b7c191a53abe0c10435e5303ce01c288b9e0`) was imported through the pinned SculptGL browser's actual `#alphaopen` file-change route. The runtime was the hash-checked host mirror of the unmodified `79b24bf6e1818cbb468c53cfe49783de419fd3e58f72b220aeb9308932e47600` bundle. Read-only inspection after the ordinary image-loader callback found the Draw tool's selected imported alpha and all 256 raster values: left half 64, right half 192. The runtime texture bytes have SHA-256 `ce8b95aded040da72778599465564e95b3cde5290441dbd33ac55627ba93ad19` and FNV-1a64 `d30772f17fc5b725`, equal to the Source Brush capture in C165.

With a diagnostic identity alpha frame and side 1, the pinned runtime's actual `Picking.getAlpha` returned primary values `[192,192,64,64,0]/255` at local X `[-0.75,-0.25,0.25,0.75,2]`; X-mirrored picking returned `[64,64,192,192,0]/255`. This proves the imported texture and these nearest-sampling points for the reference runtime. OBrush's bounded JPEG decoder has an all-pixel 64/192 unit oracle, and its C165 browser stroke captured the identical FNV texture checksum. It does **not** pair the same mesh's vertex displacements or prove arbitrary alpha images, brush response, latency or SculptGL family parity.
