# C193 world-axis rotation arcs

The normal OBrush Transform viewport now draws X/Y/Z rotation arcs. A pointer-down captures a projected arc tangent and the camera-frozen viewport. Absolute travel along that tangent maps to an angle by the pinned SculptGL `Gizmo._updateRotateEdit` rule, `-7 × tangent distance / min(viewport width, viewport height)` radians, modulo one turn. The reference is `src/editing/Gizmo.js` at commit `8e45dafc0f7906e5238dfffc1a2df742bd25f29d` (SHA-256 `e56a6e70f0eb2d53dd30240aa8a93c16258a3605b0a885aab743b6cb07df3c6c`). OBrush draws its own complete projected arcs and captures a local segment tangent; physical reference hit regions, arc shapes and colors have not been paired.

The held preview composes world-pivot rotation into the same model, normal, contour, wire and transparent-order paths used by other transforms, without editing the saved document or mesh buffers. Release applies one selected-group shared-core transform, optionally weighted by each vertex's unprotected mask fraction. Escape and focus cancellation clear the rotation preview; a test explicitly starts with a nonzero rotation preview and confirms saved geometry and Redo remain exact. A renderer test independently checks that a 90-degree world-Z preview moves a point around an offset pivot and rotates its view-space normal.

An isolated normal-browser run passed all 24 transform workflows. Actual X/Y/Z arc drags previewed `[-13.374679565429688,0,0]`, `[0,-13.298007011413574,0]` and `[0,0,-13.037650108337402]` degrees. Their source-rule expectations from captured pointer-down tangents were `-13.374678328212223`, `-13.29800809267285` and `-13.037648997304059` degrees. All other rotation components stayed exactly zero. Held VBO/IBO bytes and document revisions stayed unchanged; the rendered matrix changed; each release committed once and Undo/Redo recovered exact saved states. Independent point arithmetic had maximum component errors `2.884470207131784e-8`, `1.1711101954858805e-7` and `1.1877727779108227e-7` respectively. No GL or JavaScript runtime errors were recorded.

On the independently authored two-part mask fixture, a small Z-ring drag previewed both selected objects and committed `-1.8574528694152832` degrees. Independent `old + (1-mask) × (rotated-old)` arithmetic had maximum component error `2.3106911279519027e-7`; 76 fully protected vertices stayed exact, 380 partially protected vertices were present, and 456 vertices changed. The result is `.artifacts/transform-browser/rotate-group-c193-424633a2-8aa2-47e9-b2c5-8ebe06f739d7/result.json` (SHA-256 `26ec63fb245c3aad9ff34b78ffecf9936b701282cd6a01afadd1ae7ca0753c8f`), using served WASM SHA-256 `8938b3bc7213880a36dbd656cb6b41c4ba9555b8eaf61bad842eb6b8271e76d6`.

The first browser run failed because an arc captured a Plane X pad click; the corrected pad priority passed the plane workflows. That failed result is `.artifacts/transform-browser/rotate-z-c193-e1f7e2a0-9090-441f-a996-424f68a24bfd/result.json` (SHA-256 `acd5f0150c6b0a290bca8f76a915be1bfbee7235e9d9f148db4642a58439c078`). The next run failed an angle oracle that used the tangent at the unrounded displayed handle point rather than the segment captured at the rounded pointer-down; its result is `.artifacts/transform-browser/rotate-z-c193-priority-f977176d-ac11-4c8e-a01d-1e96042266f2/result.json` (SHA-256 `89eed4c221ec2c9ebcb1dd15c4835f7336313522c78e12fa560889deb2837f2d`). The final harness checks the captured tangent and retains both failures as evidence.

`cargo fmt --all -- --check`, complete locked workspace tests, strict native and wasm32 Clippy, `scripts/build-web.sh`, and `scripts/package-macos.sh` passed; the macOS app signature verified. The workspace test log is `.artifacts/rotation-c193/workspace-tests.log` (SHA-256 `28f7a1cd6ae7d3f5d2b7446b96f7b382ec5e845e77dfb609b7ff0be7588e6c79`). The later focused cancellation test also passed after making its preview rotation nonzero; that test-only edit does not change the served build.

The pinned source declares and draws a view-facing `ROT_W` circle, but its `onMouseDown` and `onMouseOver` dispatches handle `ROT_XYZ` and do not route `ROT_W` into a rotation update. Its live behavior needs a paired runtime check before treating view-axis rotation as a reference feature. Other camera poses, rotated/scaled multi-part meshes, physical pointer/pen input, source-matched arc hit regions, retained-detail mask transport and sustained large-mesh latency remain open. This does not establish Transform-family, SculptGL or ZBrush parity.
