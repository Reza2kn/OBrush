# C102: controlled coarse edit after static subdivision

The [C101 navigation comparison](SCULPTGL_UV_NAVIGATION_C101.md) covered an unedited Lower/Higher cycle. C102 isolates the next open operation: after importing the same independently authored all-seamed tetra, quad cube and mixed pyramid OBJ fixtures and adding one smooth level, Lower, move one physical coarse vertex by `(0.125, -0.09375, 0.0625)`, then Higher. The pinned SculptGL reference uses its real import, Subdivide, Lower and Higher controls. The single vertex edit is deliberately applied directly to its coarse typed array and geometry update; the Rust probe makes the same direct edit. This separates static-level synthesis from the two applications' different brush responses. It is **not** a normal brush, history, usability or performance test.

Faces and fine vertices are associated by their pre-edit physical positions. The first source coarse vertex maps to Rust vertex 0 for tetra and cube, and vertex 3 for the pyramid because SculptGL optimizes vertex order on import. The complete reference snapshots, typed-array residuals, neighbor IDs, before/after partial predictions and Rust probe outputs are retained in [C102 evidence](evidence/sculptgl-uv-coarse-edit-c102-0.1.20.json).

The coarse subdivision predictions already agree closely. The large mixed-pyramid error arises during residual synthesis: OBrush currently adds world-space differences, while SculptGL projects fine residuals into a frame built from raw face-averaged normals and its first vertex-ring neighbor. OBrush's stored shading normals use a different corner-angle policy, and its face/vertex order gives different first neighbors. An independent diagnostic using face-averaged normals computed from Rust geometry **and the measured reference neighbor mapping** brings the final absolute position difference to at most `1.4902e-8`, `5.9605e-8` and `2.9341e-8` on tetra, cube and pyramid respectively. This is an oracle calculation, not delivered OBrush behavior: it consumes neighbor identities observed from SculptGL. A general implementation must reproduce the relevant ring choice (or establish a differently specified tolerance), retain bounded shared-core behavior, preserve old project semantics and pass normal browser editing and history checks.

An exploratory Rust normal-frame change that used OBrush's existing shading normals and first incident-face neighbor failed the paired comparison: its maximum displacement errors were `4.4704e-8`, `0.00054223` and `0.037433`. The candidate was removed; the final `multires.rs` and delivered WASM remain byte-identical to C101. The failed trial outputs are retained. The C102 reference instance closed cleanly with no JavaScript exception or console error. Strict workspace and target checks are recorded in the evidence file. No SculptGL or ZBrush subdivision parity is claimed.
