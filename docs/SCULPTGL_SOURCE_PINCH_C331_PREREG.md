# C331 independent Float32 picker calibration: pre-capture contract

Frozen before any C331 browser capture. C329's `1e-8` direct picked-center gate failed in both polarities and remains failed; C331 must not rescore those receipts. This is a new calibration experiment, not a Pinch geometry comparison or a parity claim.

## Static causal calculation from the retained C329 capture

The reference uses gl-matrix's default `Float32Array` for camera viewport, projection and the inverse world-to-screen matrix. `Camera.unproject` stores its *output* in an ordinary JavaScript array, and Picking stores `_interPoint` in an ordinary array. OBrush computes its scene ray intersection in `f64` then converts the local hit to `f32` for the brush. Thus the likely discrepancy is rounded reference matrix coefficients, not a Float32 quantization of a near-zero final picked Y. The C329 off/full Source setup recorded projection Y `2.0006802082061768`, with a 768-pixel canvas and center Y=384. For this axis-aligned camera:

```
S = f32(384 * 2.0006802082061768) = 768.26123046875
A = f32(1 / S)                   = 0.0013016406446695328
B = f32(-384 / S)                = -0.4998299777507782
384 * A + B                     = 2.9802322387695312e-8 = 2^-25
```

This exactly equals the retained C329 Source move-picked Y while OBrush reported zero. The `f32` ULP of `B` is `2.9802322387695312e-8`; its rounding error is propagated through cancellation against the approximately `0.5` first term. The ULP of a Float32 number *at* `2^-25` is much smaller (`3.552713678800501e-15`), so calling the result “one ULP of the hit” would be incorrect. Source's C329 press-picked Y was zero while its later move-picked Y was `2^-25`; triangle interpolation and contact location may affect the final pick, and the exact matrix coincidence alone does not prove the full cause. C331 independently tests that possibility.
