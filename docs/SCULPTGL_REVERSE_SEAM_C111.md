# C111: repeated Reverse across a retained UV seam

An independently authored nonplanar 5×5 quad grid has two UV charts split at physical x=2. The right chart uses distinct UV IDs with equal values along the split. The exact same OBJ bytes (SHA-256 `a77798a24a3a97abe7d74c3663357f980597acc6b47ea67b331fcbba95b4cebb`) went through the pinned SculptGL browser and OBrush's normal browser UI.

The first OBrush browser attempt recovered the 25-vertex surface to 9 vertices but rejected a second Reverse with `Reverse UV seam equivalence is inconsistent with parent corners`. The failure receipts are retained under `.artifacts/sculptgl-paint-static-runtime/reverse-c111-seam-*`. A coarse UV ID can legitimately split into several equal-valued aliases in a retained finer level; the old Reverse check incorrectly required a one-to-one map. The core now permits that split while still rejecting a fine alias that merges distinct predicted parent chart IDs. The versioned v4 hierarchy's saved-child validation retains the same inverse-map requirement.

The rebuilt OBrush browser passes two Reverse commands, 25/16 → 9/4 → 4/1 vertex/quad levels, return to the finest level with all 30 original UV coordinates and physical corner IDs, second-command undo/redo, lower/higher navigation, save/reload and exact visible GPU/save agreement. All six scoped browser cases pass; there are 36 completed downloads and 36 GPU checks. The shared-core regression covers the same split grid, both reversals, original fine UV aliases, project reload and history, plus the allowed child split and forbidden parent-chart merge.

The [paired result](evidence/sculptgl-reverse-seam-c111.json) matches oriented faces and positions exactly at import and both coarse levels. The returned fine positions differ by at most `7.450580596923828e-9` world units. All 64 input and returned face-corner UV values match. The first intermediate reference level does **not** match: one valid reference corner at physical `(2,0)` has UV `(1,0)` where OBrush has `(0.5,0)`, and another reference face-corner UV ID is `19` while the reference reports only 13 UV coordinates. Of 16 intermediate corners, 15 were readable; the largest readable UV difference is `0.5`. A second pinned-reference run exported this level through SculptGL's normal Save .obj control. The OBJ declares 13 `vt` rows but has an `f .../20` reference, and the same erroneous `(1,0)` corner; export did not change the captured scene. The exported file SHA-256 is `647fc26b9314afaf598abc5ca5d848daf97f76e8db998d171d7bce7ec2b8ef95`. The apps' first-level UV counts are 13 and 12, and their sharing partitions differ there. The comparator records these discrepancies rather than claiming seam-level UV parity. At import and return, SculptGL reports 33 UV coordinates and OBrush retains the authored 30, but their physical face-corner values and sharing partitions agree. Source import's extra unused or aliased UV rows require separate explanation.

The [comparison script](../scripts/compare-reverse-seam.py) verifies snapshot hashes, same-byte fixture identity, oriented physical faces, positions, UV values and sharing partitions. It reports out-of-range source indices as failures of full UV comparison. Pinned bundle SHA-256 is `79b24bf6e1818cbb468c53cfe49783de419fd3e58f72b220aeb9308932e47600`; no commercial source is in OBrush.

Validation on this source: `cargo fmt --all -- --check`, 2,409 workspace tests, strict native and WASM core Clippy, WASM app check, `scripts/build-web.sh`, normal owned-Chrome browser run, and `scripts/package-macos.sh` passed. The final WASM SHA-256 is `9e14c108e8859e8b8e4f1bbbc04bb62e2f5251b1ca5c0e4c918dca29a035f2f0`; the macOS app has a valid local signature. The first diagnostic browser run and first core test run failed as described above and remain in `.artifacts`.

This closes the OBrush rejection for this seam fixture. Intermediate UV behavior against SculptGL, broader seam layouts, mixed topology, native GUI behavior and sustained million-vertex responsiveness remain open. Browser sculpting still uses Rust/WASM CPU geometry and WebGL2 rendering; the separate WebGPU prototypes are not shipped as this path.
