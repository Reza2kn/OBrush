# C131: duplicate every selected part

The normal OBrush scene-panel Duplicate button previously copied only the active part when several parts were selected. `obrush-core` now stages a copy of each selected part in selection order, validates every intermediate and final scene before publishing any change, and records one undo step per copy. The browser button uses this shared document operation. The original last-selected part becomes active after the copies are appended, matching the observed SculptGL action.

The independent three closed-box SGL fixture from [C130](SCULPTGL_SELECTED_DELETE_C130.md) is 1,560 bytes with SHA-256 `939110d73dec934f0af70fb5c364eeb18f3ce18608449fe76804896c50c9c0ae`. Under pinned SculptGL revision `8e45dafc0f7906e5238dfffc1a2df742bd25f29d`, physical Shift-click selection ends at indices `[2,1]`. Its visible Duplicate action appends the selected right and center boxes at indices 3 and 4, respectively. The selected original center box becomes active. One Undo leaves four boxes; a second Undo leaves three and restores `[2,1]`; two Redos return five. SculptGL's copy operation reorders vertex arrays, so comparisons here use part geometry and behavior rather than raw vertex-array order.

The normal OBrush browser imports the same fixture. Scene-panel Ctrl-clicks end at selected IDs `[3,2]`; its visible Duplicate button appends copies as IDs 4 and 5 and selects original ID 2. One ordinary Undo leaves four parts and selects copy ID 4. A second Undo restores the exact pre-duplicate 7,778-byte `.obrush` project, SHA-256 `1159d48c65b426d5f407bf4085567d1b00dc8c65da38442e958e4b3e3206f0bd`. Two Redos restore the exact post-duplicate 10,390-byte project, SHA-256 `2f7ea4787a2468f7b12024bb68b76757988f51d2f629889f05ae8bfc7542180a`. The normal Save project button captured the Undo state because the separate WebGPU resident diagnostic refuses capture on a redo branch. Both browser runs report zero console errors, exceptions and cleanup errors. The tested app WASM SHA-256 is `a7bec4a32a948ab861a14c4559710f207cf0e5be21a5b801576dffbd7f3de42a`.

The shared-core test uses a richer three-part document, checks that copies retain each selected part's complete payload, and verifies exact whole-project Undo twice and Redo twice. The copied parts initially occupy the same coordinates as their sources, as in SculptGL. Larger scenes, all payload types, native GUI interaction, other selected-group actions and complete SculptGL parity remain open.

Final `cargo fmt --all --check`, 100 workspace/all-target test-result summaries (**2,457 passed, zero failed, one ignored**), strict native and WASM Clippy, and `scripts/build-web.sh` passed. Browser execution used that web build. `scripts/package-macos.sh` produced an ad-hoc-signed app accepted by `codesign --verify --deep --strict`; its executable SHA-256 is `5d13eee35e7167283efeef6eaeaf225f7f2e0057e384de04042ac2de3f0f774f`. Native GUI interaction remains untested.

The [machine-readable evidence](evidence/sculptgl-selected-duplicate-c131.json) points to raw pinned-source and OBrush browser records retained in `.artifacts/scene-duplicate-c131/`. These measurements establish this selected-group Duplicate case only; they do not establish a general WebGPU performance result or full scene parity.
