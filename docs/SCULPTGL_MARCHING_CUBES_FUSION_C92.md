# Selected-mesh Marching Cubes fusion — C92

OBrush now has a selected-SubTool Marching Cubes command in the shared Rust core and the native/browser inspector. It voxelizes the selected visible solids together, replaces only those parts with one active closed mesh, and commits one undoable scene change. The unselected parts remain in place. Source order matters at overlapping voxel ties, so the implementation retains the order of the actual selection. An explicit Flatten control is required before consuming retained levels, layers, or Morph Targets; source-origin/affine parts still reject. UV loss follows the existing explicit remesh control.

The paired fixture comprises two independently authored, overlapping colored/material boxes imported as separate OBJ parts. The pinned SculptGL run selects right then left and uses Marching Cubes resolution 16 with Relax off and on. OBrush uses the same source bytes and selection order. Both outputs have 1,056 vertices and 2,108 triangles; after a bijective vertex mapping, all 2,108 oriented triangles match. Native-core RGB (3,168 values), roughness/metallic (2,112), and unmasked weights (1,056) match exactly for both Relax settings. Maximum/RMS native world-position differences are `1.3521e-7`/`8.7114e-8` with Relax off and `3.2399e-7`/`1.0736e-7` with Relax on.

An isolated Chrome run used the visible inspector to import and select both parts, set resolution 16, fuse, save, undo, and redo. Its saved meshes and actual WebGL2 buffers agreed. Against the reference, all 2,108 mapped oriented triangles match. Maximum/RMS browser-save world-position differences are `1.4507e-7`/`8.8275e-8` (Relax off) and `3.2460e-7`/`1.1379e-7` (on). Browser-save maximum RGB and material scalar differences are `2.706e-8` and `2.384e-8`; unmasked weights match exactly. The served WASM SHA-256 is `d48f110d892aaa766831d58cb1da3cc810588e2f11911ff5e5378475ee4c54a8`.

The first two paired comparisons retained a one-unit RGB discrepancy at voxel overlap ties; changing to the reference selection order resolved it. The first browser harness attempt failed because it read a `metrics` property from a saved-project return value; the corrected harness passed both cases. The first strict WASM Clippy run caught a native-only enum variant and passed after a target guard. Failed receipts remain in `.artifacts`.

This is one resolution and one intersecting-pair fixture. It does not verify arbitrary selected geometry, mixed UV inputs, source-origin/affine transforms, reference UI selection ergonomics, sustained performance, WebGPU integration, or complete SculptGL remeshing parity. The production browser still computes geometry in WASM and renders through WebGL2. The separate WebGPU proof-of-concept has not been integrated.

The exact fixture, reference, source/build, numeric comparison, browser and check records are in [the C92 evidence](evidence/sculptgl-marching-cubes-fusion-c92-0.1.20.json).
