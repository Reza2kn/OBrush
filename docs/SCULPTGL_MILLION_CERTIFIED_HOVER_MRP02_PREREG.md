# MRP02: certified Source hover picking investigation

This is a separate architectural investigation first drafted on integrated product `f053e5be449a5d11866bee5e18a169f41e077dd3`. It does not change the frozen C292 999,002-vertex SGL fixture SHA-256 `dfb5316f62e392e633f03cb662dcb12215ed165a71a9ae72a3fd639528731afe`, 60-second/400-requested-moves/s protocol SHA-256 `234870ed03a240931a22f421968917efaeed8becc1df834c998bbe3e9c101a33`, or global gates: active RAF P95 ≤33.34 ms, active RAF maximum ≤250 ms, app callback CPU P95 ≤16.667 ms, release acknowledgement ≤100 ms. C292's fresh browser baseline failed all four (66.7/600/63.2/134.7 ms). Its read-only viewport timer measured 34.88 ms mean in `viewport()`, including 15.41 ms queued-dab processing and an unassigned 16.87 ms residual. Those nested means are not additive and do not prove the residual is a pick. C292 used an older product revision and remains historical context, **not a matched control** for MRP02.

## Attribution gate, before product code

The active Source Brush viewport currently calls `self.pick()` for cursor drawing after processing dabs. That calls `Document::raycast_scene()`, which checks scene structure, calls `mesh.validate()` and intersects the original indexed triangles (up to the two-million-triangle work limit). The brush has already performed a distinct Source contact query. The hypothesis is that this duplicate full-scene hover query explains ≥10 ms/useful frame of C292's residual. Freeze a **read-only** timer around this exact `self.pick()` expression, with occurrence/no-hit counts, separately from existing `viewport`/core/renderer timings. Keep the same conditional evaluation and cursor result. Compare timer sample and total-time deltas between the harness's pre-press metrics and its **first** released-tail sample; zero samples in that interval rejects this cursor-path hypothesis. The interval includes the frozen harness's one-second pre-press pause and the release event, which are disclosed rather than called active-stroke samples. A same-state host diagnostic independently times `Mesh::validate()`, `Mesh::raycast_indexed()` and the actual `Document::raycast_scene()` path on the exact fixture; the host numbers are attribution only, never substituted for browser latency. Run one owned-browser frozen cohort and the independent full-file auditor. Preserve raw failure and read-only patch/build hashes, then remove the probe. Do not attempt product code unless mean hover pick is ≥10 ms per useful frame in that interval or ≥25% of app callback CPU and the independent split shows a real triangle-scan/validation target.

## Conditional candidate architecture

If the attribution gate passes, reuse the core-created `CertifiedSourceRenderSnapshot` that already binds an immutable `Arc<Mesh>` to the accepted `SourceGeometryNormalState` immediately after a controlled dab. Its retained ordered tree updates with each accepted edit and supplies conservative candidate original-face rows for a ray. Add a core-private certified scene-hit entry that consumes **that exact immutable pair** and intersects candidate original triangles in ascending row order using the existing f32/f64 ray math, nearest-distance and equal-distance tie behavior. For scenes with any other visible object, unsupported mesh/pose, absent certificate, stale app revision or mismatched displayed snapshot identity, use the existing public `Document::raycast_scene()` path. Do not cache a raw mesh pointer or allow an arbitrary caller to construct a certificate. The certificate's immutable `Arc` is the lifetime/ownership boundary; no full mesh validation is skipped for uncaptured or mutable documents. Keep the existing public picker and Source contact query unchanged. Bound candidate allocation by original face count and the existing tree limit, reject nonfinite rays, and preserve original face IDs and no-hit behavior. If a precise same-state differential fixture reveals any miss or changed hit word, reject the candidate.

Before implementation, build independent paired fixtures for identity and affine scenes, overlapping visible subtools, duplicate/equal-distance triangles, no-hit/outside rays, grazing and boundary rays, no-contact cursor, and a retained tree after many deforming dabs. For every exact ray compare baseline and candidate hit presence, active object, original triangle row, barycentric and local/world positions/normals/distances **bitwise** where the same arithmetic branch applies. Compare cursor visibility, screen center/radius and no-hit disposition; this is a display behavior contract, not only a sculpt-file check. Check stale certificate after revision, import, Undo/Redo, cancelled stroke and selection switch falls back rather than rendering a stale contact. Same-state native and WASM microbenchmarks must predict ≥10 ms useful-frame saving without worse peak memory before a second frozen browser cohort.

The candidate's owned-browser run must preserve exact Before/After/Stable/Undo/Redo public project bytes, one-step history, finite geometry, unchanged non-position channels and faces, no new affected-face degeneracy/reversal, endpoints, and independent actual GPU VBO position and Source display-normal words. It must have zero app/GL/queue overflow errors, no worse release queue, no worse RAF P95/max or app CPU P95 than the **matched MRP02 control**, and at least a 10 ms reduction in the named browser hover-pick stage on matched state. Different delivered-dab counts make the 60-second comparison observational; exact same-state timing pairs establish local causality. **Product promotion requires all four unchanged global responsiveness gates as well as correctness.** A local win that leaves those gates open is reported and reverted, not called SculptGL parity. Preserve every failed result and restore the ordinary build after removing rejected code.
