# Preregistered opt-in Source display-normal trace capture

Static design frozen 2026-10-19 against root `f9d7e24`. No product code, browser run, Cargo run, root checkout, public project format, or `SP-WORKER-01` verifier was changed. The earlier 100k receipt `100k-worker-588e764b-eb00-47df-89aa-2d2f0a3ef260` remains `missing_replay_evidence`; its SHA-256 is `0424c256883651b79c08ae9f3cc1b5c5ce323bfefcab6d8131ff26a237e93857`. This proposal is for a **separate diagnostic run**, not for a timed admission pair. Trace collection can perturb frames and Worker messages, so its timings cannot be compared with the uninstrumented 60-second cohort.

## Smallest source tap

Gate this path behind an explicit diagnostic-only `source-worker-display-trace-v1` URL flag in addition to `source-worker-held`. Default production and normal held Worker calls must not allocate a trace buffer or change their response bytes. The frozen cohort is Source Draw/Brush row 0, no symmetry, no culling, no alpha and no pressure factors; do not generalize a one-selected-set-per-dab trace to mirrored or other tools. Reject trace admission when that exact setting fingerprint differs.

`SourceWorkerTransaction::apply_input` in `crates/obrush-core/src/source_worker_transaction.rs` returns only `SourceGeometryControlledReport` counts. The primary geometric selection is temporarily owned by `PreparedControlPass.selected` inside `SourceGeometryStroke::apply_validated_controlled` in `crates/obrush-core/src/source_geometry.rs`, but that list is **not automatically the normal-refresh list**: culling or an early no-op can change whether and which rows refresh. Add a read-only opt-in diagnostic sidecar to that *successful* operation after all fallible geometry/cache/history work has succeeded and before `prepared` is dropped. It must copy the exact IDs actually handed to the retained state's `refreshed`, `refreshed_after_selected_write`, or `advance_private` transition; an accepted pass with no retained normal refresh records `selected: []` even when `record_history_noop` adds vertices to the later history union. Include no-coordinate-change and zero-intensity refresh cases when they really run. Do not derive refresh IDs from changed positions, affected chunks, `selected_vertices` counts, `render_selected_chunks`, or final `mesh.normals`. For the frozen one-pass/no-culling scope, assert exactly one primary pass and no mirror pass. A future multi-pass trace must record pass order and post-pass positions separately before replay is extended.

In `crates/obrush-app/src/source_geometry_browser_worker.rs::BrowserSourceWorkerStroke::apply`, after `transaction.apply_input` succeeds and the existing `SourceWorkerPreviewRow` packet is validated, take the sidecar selection and record sorted unique IDs plus only `[id,post_x,post_y,post_z]` rows whose *position* words changed from `before_position` to `after_position`. Those existing rows are already checked against the certified sparse chunk envelope. An accepted dab with no position edits still needs its selected IDs and an empty position list. Bind its monotonically increasing sequence and actual `web/source-geometry-worker.js` apply reply ID. A failed dab must emit no accepted trace event; failure, trace allocation overflow, or missing selection marks the diagnostic **incomplete** without changing geometry, history, reply success or the public document. The recorder must not call a second brush, recompute selection from the final mesh, or mutate Worker positions/normals.

Before `SourceWorkerTransaction::finish` consumes its stroke, capture the authoritative `SourceGeometryStroke.history_selected` union through a diagnostic-only read accessor. This is the exact bool selection attached to the Source history event by `Document::attach_source_selection_history` / `end_source_geometry_stroke` in `source_geometry_document.rs`; it may include no-op selections that a union of changed positions would omit. Bind the copied sorted IDs to the successful final reply only; discard if finish or publication rejects. The ordinary UI's subsequent Undo and Redo remain unchanged. Their **position rows** can be generated offline by a bounded comparison of the already captured complete Before/After/Undo/Redo public Save files: include all restored changed rows in the trace, but never infer the history-selected IDs from those differences. Check that every changed history row belongs to the captured history union. `source_history.rs::prepare_source_history` and `SourceGeometryNormalState::refreshed_for_history` explain why the replay must start each transition from the current retained field and refresh only those IDs.

## Bounded transport and receipt

Use a private, versioned diagnostic channel from `BrowserSourceWorkerStroke` through `web/source-geometry-worker.js` and `web/source-worker-held-input.js`, never the `.obrush` project or ordinary preview/final delta. Prefer length-prefixed binary chunks with checked record counts/byte lengths; at most **1 MiB per accepted dab**, **128 MiB total**, and **24,000 dab records** for a 100k run. A bounded JS collector or test harness may accumulate/stream chunks to an ignored `.artifacts` receipt; cap its in-memory bytes at the same 128 MiB and record overflow before refusing additional trace records. No trace allocation failure may reject an otherwise valid sculpt. Every chunk needs a sequence, byte length and checksum; the final receipt needs protocol/version, source/served WASM+JS hashes, original fixture and Before project hashes, active SubTool/face-order identity, per-dab accepted Worker message IDs, final history-union IDs, all chunk hashes, overflow state, and the whole artifact SHA-256. The harness can bind the completed trace to `result.json` SHA-256 after that file is written. Any absent, dropped, duplicated, reordered, truncated or over-cap record is `missing_replay_evidence` or `invalid_replay_evidence`, never a partial pass.

Translate the bounded binary capture into the JSON `obrush-source-display-replay-v1` input already accepted by `scripts/audit-source-display-normal-replay.py`, with exact `product_binding`, `result_sha256`, `before_sha256`, `accepted_dabs`, ordered `dab` events, and explicit After/Stable/Undo/Redo checkpoints. Keep the decoded JSON under its current 128 MiB limit; if expansion exceeds it, the result is incomplete rather than increasing the cap after seeing the run. Use the independent public Before face rows and positions for the Python replay. For each of five states require exact replayed/public position words, exact replayed/VBO display-normal words, one active VBO, zero GL error, and exact public file hashes. Separately retain the unchanged `SP-WORKER-01` public-mesh-normal GPU failure. A trace that merely copies product retained normals or current VBO normals as expected values is not independent and must fail review.

## Falsification before a 100k capture

Use an independently authored curved triangle/quad fixture whose public mesh normals differ from original-face display normals. A complete one- and two-dab diagnostic must match the independent replay at Before, each accepted dab, After, Stable, Undo and Redo, including a selected-but-unchanged vertex and an unselected vertex adjacent to a changed face. A deliberate one-ID deletion, position-word flip, face-order flip, duplicate sequence, mismatched Worker reply ID, omitted no-op selection, truncated chunk and over-cap trace must each fail. A cancelled gesture must retain exact public Before/redo and baseline VBO words while the trace is marked cancelled, never published as a five-state success. Then run the existing 100k fixture once with trace enabled, record all costs/limits and keep the result separate from uninstrumented performance evidence. No edited-state GPU correctness, Worker responsiveness, SculptGL or ZBrush parity claim follows until the independent replay and the applicable versioned browser admission gates pass.
