# C106: chained source-static detail transport

The C105 normal-frame policy matched one retained level. This checkpoint tests two smooth source-static levels from the same independently authored all-seamed tetra, quad cube and mixed pyramid OBJ files. In the pinned SculptGL browser, each file is imported, subdivided twice, lowered to the base, edited by the controlled physical-vertex delta `(0.125, -0.09375, 0.0625)`, then raised through both levels with the real GUI controls. The direct typed-array edit isolates hierarchy synthesis from different brush implementations. OBrush follows the same sequence through `Document` and `Mesh::import_obj`.

The first paired run found a real second-level gap: maximum final-position component errors were `0.000995398`, `0.000151634` and `0.010241102` for tetra, quad cube and pyramid. First-level values already agreed within `5.9605e-8`. The retained failure is indexed in [C106 evidence](evidence/sculptgl-two-level-frame-c106-0.1.20.json).

The source's generated `MeshResolution` faces are not re-optimized. They retain the previous subdivision's face order, while some triangle child faces rotate cyclically relative to OBrush's physically equivalent face rows. C106 now carries each generated face's source order and cyclic orientation in a bounded topology map. A chained map uses those oriented rows to choose the next level's first ring neighbor. Its optional, validated `source_root_order` field in versioned `.obrush` JSON preserves this mapping if lower levels are deleted and the project is reopened; older v3 files without the field continue to load using the original-root reconstruction policy.

On the same three paired fixtures, all 182 second-level first-neighbor IDs match the pinned source after physical vertex mapping. The maximum final-position component errors after the correction are `2.9803e-8`, `5.9605e-8` and `2.9803e-8` for tetra, quad cube and pyramid. A shared-core regression reloads the saved two-level stack before the edit and checks every fine position; another deletes the lower level, reloads, and checks that subsequent transport remains exact to the in-memory stack. A malformed saved face-order ID is rejected before installation.

The official rebuilt WASM passed an isolated Chrome run with eight cases, 51 completed downloads and 51 saved-project/visible-GPU checks. Its ordinary Draw stroke on a 1,536-quad UV grid moved 18 of 1,538 coarse vertices and propagated to 939 of 24,578 vertices at the second fine level. Undo/redo, release quiet, project reload, and all declared two-level browser gates passed. The final source also passed `cargo fmt`, 2,403 workspace tests across 71 groups (one ignored generator), strict native/WASM Clippy, the WASM target check and both official build scripts; the local macOS signature verified. Exact hashes, numeric comparisons, retained failures and browser records are in [C106 evidence](evidence/sculptgl-two-level-frame-c106-0.1.20.json).

These comparisons cover one direct coarse vertex edit, two smooth levels, three small UV-seamed shapes and the named browser delivery workflow. They do not establish normal brush-response parity, linear-edge two-level reference behavior, arbitrary topology, repeated/fine-level edits, native GUI feel, million-vertex responsiveness or complete SculptGL subdivision parity. WebGPU compute/draw integration remains separate.
